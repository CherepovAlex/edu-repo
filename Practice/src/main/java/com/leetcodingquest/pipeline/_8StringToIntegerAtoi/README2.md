Приветствую! Я ваш преподаватель по Java. Сегодня мы разберем одну из классических задач на интервью в Big Tech компаниях — LeetCode 8. String to Integer (atoi).

Эта задача кажется простой, но на самом деле она проверяет ваше умение работать с крайними случаями (edge cases), понимание типов данных и умение писать чистый, безопасный код.

Стратегия решения
Чтобы решение было оптимальным, мы должны пройти по строке один раз (O(n) по времени) и использовать минимум дополнительной памяти (O(1) по пространству).

Алгоритм будет таким:
1. Игнорирование пробелов: Пропускаем все ведущие пробелы.
2. Проверка знака: Если следующий символ + или -, запоминаем знак.
3. Чтение цифр: Считываем цифры, пока они есть.
4. Проверка переполнения (Overflow): Это самый важный момент. Поскольку Java int имеет пределы [-2^31, 2^31 - 1], мы должны проверять переполнение до того, как умножим текущее число на 10 и добавим новую цифру. Если переполнение произойдет, мы сразу возвращаем граничное значение.
5. Возврат результата: Применяем знак и возвращаем число.

class Solution {
    public int myAtoi(String s) {
        // Если строка null или пустая, возвращаем 0
        if (s == null || s.isEmpty()) {
            return 0;
        }

        int index = 0;
        int n = s.length();
        int sign = 1; // По умолчанию знак положительный (+1)
        int result = 0;

        // Шаг 1: Игнорируем начальные пробелы
        while (index < n && s.charAt(index) == ' ') {
            index++;
        }

        // Если после пробелов строка закончилась, возвращаем 0
        if (index == n) {
            return 0;
        }

        // Шаг 2: Проверка знака
        if (s.charAt(index) == '-') {
            sign = -1;
            index++;
        } else if (s.charAt(index) == '+') {
            // Если плюс, просто переходим к цифрам, знак остается 1
            index++;
        }

        // Шаг 3: Преобразование цифр в число
        while (index < n && Character.isDigit(s.charAt(index))) {
            char c = s.charAt(index);
            int digit = c - '0'; // Преобразуем символ цифры в целое число

            // Шаг 4: Проверка на переполнение (Overflow)
            // Нам нужно сделать: result = result * 10 + digit
            // Но мы должны проверить, не выйдет ли это за пределы int.MAX_VALUE
            
            // Если result уже больше, чем MAX_VALUE / 10, 
            // то при умножении на 10 он точно переполнится (или будет равен, но потом +digit превысит)
            if (result > Integer.MAX_VALUE / 10) {
                // Если знак положительный, возвращаем MAX_VALUE
                if (sign == 1) {
                    return Integer.MAX_VALUE;
                }
                // Если знак отрицательный, нужно проверить MIN_VALUE
                // MIN_VALUE = -2147483648, MAX_VALUE = 2147483647
                // Для отрицательных чисел граница жестче на 1 единицу
                // Если result == MAX_VALUE / 10 (214748364), то следующий шаг:
                // result * 10 + digit = 2147483640 + digit
                // MIN_VALUE = -2147483648. 
                // Если digit > 8, то 2147483640 + 9 = 2147483649 > 2147483648 (по модулю), значит переполнение
                if (sign == -1 && result == Integer.MAX_VALUE / 10 && digit > 8) {
                    return Integer.MIN_VALUE;
                }
                // Если digit <= 8, то 2147483640 + 8 = 2147483648, что равно -MIN_VALUE (по модулю), 
                // но так как мы работаем с положительным result, а знак -1, 
                // то фактически мы формируем число -2147483648, что допустимо.
                // Однако, если result > MAX_VALUE/10, мы уже выше границы для положительных.
                // Для отрицательных: если result > 214748364, то переполнение.
                // Если result == 214748364 и digit > 8, то переполнение.
                // В остальных случаях, если result > MAX_VALUE/10, это переполнение для любого знака?
                // Нет. Для знака -1, граница -2147483648.
                // Если result = 214748364, то следующее число по модулю 214748364X.
                // Если X > 8, то > 2147483648 -> переполнение -> MIN_VALUE.
                // Если X <= 8, то <= 2147483648 -> допустимо.
                // Но если result > 214748364 (т.е. 214748365), то 214748365X > 2147483648 -> переполнение.
                
                // Упростим логику проверки переполнения для обоих знаков:
                // Мы хотим проверить: result * 10 + digit > MAX_VALUE (для sign=1)
                // Или: -(result * 10 + digit) < MIN_VALUE (для sign=-1) => result * 10 + digit > -MIN_VALUE = 2147483648
                
                // Давайте переформулируем проверку более универсально:
                // Если sign == 1: проверяем result > (Integer.MAX_VALUE - digit) / 10
                // Если sign == -1: проверяем result > (Integer.MAX_VALUE - digit) / 10 ? Нет.
                // Для отрицательных: MIN_VALUE = -2147483648.
                // Если мы строим число по модулю, то максимальное допустимое значение по модулю для sign=-1 это 2147483648.
                // Для sign=1 это 2147483647.
                
                // Перепишем проверку внутри цикла более четко:
            }
            
            // Более чистая проверка переполнения:
            // Если результат уже слишком велик, чтобы умножить на 10 и добавить digit без переполнения
            if (result > Integer.MAX_VALUE / 10 || 
               (result == Integer.MAX_VALUE / 10 && digit > (sign == 1 ? 7 : 8))) {
                return sign == 1 ? Integer.MAX_VALUE : Integer.MIN_VALUE;
            }

            // Шаг 5: Обновляем результат
            result = result * 10 + digit;
            index++;
        }

        // Применяем знак
        return result * sign;
    }

Пошаговый разбор примеров
Давайте проследим за вычислениями для каждого примера.

Пример 1: s = "42"
1. Инициализация: index = 0, sign = 1, result = 0, n = 2.
2. Пробелы: s.charAt(0) = ‘4’ (не пробел). Цикл пропуска пробелов не выполняется. index остается 0.
3. Знак: s.charAt(0) = ‘4’ (не ‘+’ и не ‘-’). index остается 0.
4. Цикл цифр:
* Итерация 1: index = 0. c = '4', digit = 4.
* Проверка переполнения: result (0) > 214748364? Нет.
* result = 0 * 10 + 4 = 4.
* index становится 1.
* Итерация 2: index = 1. c = '2', digit = 2.
* Проверка переполнения: result (4) > 214748364? Нет.
* result = 4 * 10 + 2 = 42.
* index становится 2.
* Конец цикла: index (2) не меньше n (2). Цикл завершается.

5. Возврат: result * sign = 42 * 1 = 42.
* Результат: 42.

* index = 0: s.charAt(0) = ’ '. index становится 1.
* index = 1: s.charAt(1) = ‘-’. Не пробел. Цикл останавливается.

* sign = -1.
* index становится 2.

4. Цикл цифр:
* Итерация 1: index = 2. c = '0', digit = 0.
* Проверка переполнения: 0 > ...? Нет.
* result = 0 * 10 + 0 = 0.
* index становится 3.
* Итерация 2: index = 3. c = '4', digit = 4.
* Проверка переполнения: 0 > ...? Нет.
* result = 0 * 10 + 4 = 4.
* index становится 4.
* Итерация 3: index = 4. c = '2', digit = 2.
* Проверка переполнения: 4 > ...? Нет.
* result = 4 * 10 + 2 = 42.
* index становится 5.
* Конец цикла: index (5) не меньше n (5).

5. Возврат: result * sign = 42 * -1 = -42.
* Результат: -42.

Пример 3: s = "1337c0d3"

Почему это решение оптимально?
1. Время: Мы проходим по строке ровно один раз. В худшем случае (вся строка состоит из цифр) мы выполняем O(n) операций.
2. Пространство: Мы используем только несколько переменных (index, sign, result), независимо от длины строки. Это O(1) дополнительной памяти.
3. Безопасность: Мы явно проверяем переполнение, используя математические свойства границ int, чтобы избежать непредсказуемого поведения при арифметических операциях.

Это решение полностью соответствует требованиям LeetCode и является эталонным для данной задачи.
