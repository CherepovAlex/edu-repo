# LeetCode 3886. Сумма сортируемых целых чисел — решение на Java

Разберём задачу как на занятии по Java: сначала поймём условие, затем выведем алгоритм, напишем код с комментарием к каждой строке и вручную пройдём все три примера.

Главная идея: число \\(k\\) подходит, если оно является делителем длины массива \\(n\\), а после циклических сдвигов каждого блока длины \\(k\\) весь массив можно расположить в неубывающем порядке.

## 1. Разбираем условие задачи

Дан массив `nums` длины `n`. Нужно найти все подходящие значения `k` и вернуть их сумму.

Число `k` должно удовлетворять двум условиям:

1. `n % k == 0` — массив делится на блоки одинаковой длины `k` без остатка.
2. Каждый блок можно циклически сдвинуть так, чтобы весь массив оказался отсортирован по возрастанию или с повторяющимися элементами (то есть в неубывающем порядке).

Циклический сдвиг — это перенос элементов с одного конца блока на другой с сохранением их порядка.

Например, блок `[3, 1, 2]` можно циклически сдвинуть влево:

`[3, 1, 2] → [1, 2, 3]`

Но блок `[7, 6, 5]` так отсортировать нельзя: циклические сдвиги дают только `[7, 6, 5]`, `[6, 5, 7]` и `[5, 7, 6]`.

## 2. Как решить задачу эффективно

Перебирать все числа от `1` до `n` необязательно. Нас интересуют только делители `n`.

Например, если `n = 6`, возможные значения `k` — это `1`, `2`, `3`, `6`.

Для каждого делителя `k`:

1. Разбиваем массив на блоки длины `k`.
2. Проверяем, можно ли циклическими сдвигами каждого блока получить отсортированный массив.
3. Если можно, прибавляем `k` к ответу.

Чтобы проверка была быстрой, воспользуемся важным наблюдением.

Циклические сдвиги не меняют набор элементов блока. Поэтому каждый блок должен содержать именно те элементы, которые могут занимать соответствующие позиции в итоговом отсортированном массиве. Кроме того, порядок элементов внутри блока должен совпадать с порядком отсортированного блока с точностью до циклического сдвига.

Однако для массива длиной до \\(10^5\\) неэффективно сортировать массив заново для каждого делителя. Вместо этого можно сначала отсортировать весь массив и проверять блоки относительно полученного результата.

## 3. Ключевое наблюдение: как проверить блок за один проход

Вместо сортировки каждого блока будем проверять два свойства.

### Свойство № 1. Внутри блока не больше одного циклического спуска

Спуск — это ситуация, когда следующий элемент меньше предыдущего.

Например, блок `[3, 1, 2]` имеет один обычный спуск: `3 > 1`. Если дополнительно рассматривать переход от последнего элемента к первому, получаем `2 > 3` — это неверно. Значит, имеется ровно один циклический спуск, и блок можно повернуть в отсортированный вид.

У блока `[7, 6, 5]` два обычных спуска: `7 > 6` и `6 > 5`. Циклический сдвиг не сможет отсортировать его.

Удобнее проверять циклический спуск так: для каждой соседней пары, включая последнюю и первую, считаем случаи, когда текущий элемент больше следующего. Блок подходит, если таких случаев не больше одного.

### Свойство № 2. Блоки должны правильно располагаться относительно друг друга

Даже если каждый блок можно отсортировать отдельно, итоговая последовательность может оказаться неотсортированной.

Например, при `k = 2`:

`[2, 3] | [1, 4]`

Оба блока уже отсортированы, но между блоками нарушен порядок: `3 > 1`.

Поэтому дополнительно проверяем:

\\[ \max(\text{текущий блок}) \leq \min(\text{следующий блок}) \\]

Если это условие выполняется для всех соседних блоков, их можно объединить в один отсортированный массив.

Таким образом, для каждого делителя `k` достаточно за один проход проверить циклические спуски внутри блоков и порядок между соседними блоками.

## 4. Полный код на Java с комментариями к каждой строке

```

class Solution { // Класс решения для LeetCode.
    public long sumOfK(int[] nums) { // Метод возвращает сумму всех подходящих k.
        int n = nums.length; // Сохраняем длину исходного массива.
        long answer = 0; // Используем long, чтобы безопасно хранить сумму.

        for (int k = 1; k <= n; k++) { // Перебираем возможные длины блоков.
            if (n % k != 0) { // Проверяем, делится ли n на k без остатка.
                continue; // Если нет, k не подходит по условию задачи.
            }

            boolean valid = true; // Предполагаем, что k подходит.
            int previousMax = -1; // Максимум предыдущего блока; nums[i] >= 1.

            for (int start = 0; start < n; start += k) { // Перебираем блоки.
                int end = start + k; // Индекс сразу после последнего элемента блока.
                int minValue = nums[start]; // Минимум текущего блока.
                int maxValue = nums[start]; // Максимум текущего блока.
                int descents = 0; // Количество циклических спусков в блоке.

                for (int i = start; i < end; i++) { // Просматриваем текущий блок.
                    minValue = Math.min(minValue, nums[i]); // Обновляем минимум.
                    maxValue = Math.max(maxValue, nums[i]); // Обновляем максимум.

                    int next = (i + 1 == end) ? start : i + 1; // После конца блока возвращаемся к его началу.
                    if (nums[i] > nums[next]) { // Проверяем, есть ли спуск к следующему элементу.
                        descents++; // Увеличиваем число спусков.
                    }
                }

                if (descents > 1) { // Более одного циклического спуска означает, что блок не подходит.
                    valid = false; // Помечаем k как неподходящее.
                    break; // Нет смысла проверять остальные блоки.
                }

                if (start > 0 && previousMax > minValue) { // Проверяем порядок между блоками.
                    valid = false; // Блоки нельзя объединить в неубывающий массив.
                    break; // Прекращаем проверку этого k.
                }

                previousMax = maxValue; // Запоминаем максимум текущего блока.
            }

            if (valid) { // Если все блоки прошли обе проверки.
                answer += k; // Добавляем подходящее значение k к сумме.
            }
        }

        return answer; // Возвращаем итоговую сумму.
    }
}

```

## 5. Пошаговый разбор примера № 1

Входные данные:

```
nums = [3, 1, 2]
```

Длина массива \\(n = 3\\). Делители числа 3 — это `1` и `3`.

### Проверка k = 1

Блоки состоят из одного элемента.

[3]

[1]

[2]

- Первый блок: максимум `3`.
- Второй блок: минимум `1`.
- Проверка границы: `3 <= 1` — ложь.
- Значит, весь массив отсортировать нельзя, если разрешены только сдвиги отдельных блоков длины 1.

k = 1 не подходит

### Проверка k = 3

Весь массив является одним блоком.

## [3, 1, 2]

Один циклический спуск: 3 > 1

## [1, 2, 3]

- `3 > 1` — первый спуск.
- `1 > 2` — нет спуска.
- `2 > 3` — нет спуска при циклической проверке, поскольку `2` меньше `3`.
- Всего один спуск, следовательно, блок можно отсортировать циклическим сдвигом.

k = 3 подходит

Суммируем подходящие значения:

\\[ \text{answer} = 3 \\]

Выход: `3`.

## 6. Пошаговый разбор примера № 2

Входные данные:

```
nums = [7, 6, 5]
```

Длина массива \\(n = 3\\). Проверяем делители `1` и `3`.

### Проверка k = 1

Блоки: `[7] | [6] | [5]`.

При проверке границы между первыми двумя блоками получаем:

\\[ \max([7])=7,\qquad \min([6])=6 \\]

Поскольку \\(7 > 6\\), порядок нарушен. `k = 1` не подходит.

### Проверка k = 3

Весь массив `[7, 6, 5]` — один блок.

## [7, 6, 5]

7 → 6

6 → 5

5 → 7

Два спуска: 7 > 6 и 6 > 5

Количество циклических спусков равно `2`. Это больше допустимого значения `1`, поэтому никакой циклический сдвиг не отсортирует блок.

k = 3 не подходит

Ни один делитель не подошёл:

\\[ \text{answer} = 0 \\]

Выход: `0`.

## 7. Пошаговый разбор примера № 3

Входные данные:

```
nums = [5, 8]
```

Длина массива \\(n = 2\\). Возможные делители — `1` и `2`.

### Проверка k = 1

Блоки: `[5] | [8]`.

- Максимум первого блока: `5`.
- Минимум второго блока: `8`.
- Проверяем `5 <= 8` — условие выполняется.
- Оба блока состоят из одного элемента, поэтому циклические спуски отсутствуют.

k = 1 подходит

### Проверка k = 2

Весь массив `[5, 8]` — один блок.

- `5 > 8` — нет спуска.
- `8 > 5` — нет, поскольку `8 > 5` здесь как раз верно: при циклическом сравнении последнего элемента с первым спуск есть.

Следовательно, имеется ровно один циклический спуск — `8 > 5`. Это нормально: блок можно повернуть.

## [5, 8]

## [5, 8]

Массив уже отсортирован

k = 2 подходит

Суммируем оба подходящих значения:

\\[ \text{answer} = 1 + 2 = 3 \\]

Выход: `3`.

## 8. Сложность алгоритма

Обозначим длину массива через \\(n\\), а количество его положительных делителей — через \\(d(n)\\).

- Временная сложность: \\(O(n \cdot d(n))\\), потому что для каждого делителя мы в худшем случае один раз просматриваем все элементы массива.
- Дополнительная память: \\(O(1)\\), поскольку используются только несколько переменных, а исходный массив не изменяется.

Для \\(n \leq 10^5\\) количество делителей невелико, поэтому такой алгоритм достаточно эффективен. В отличие от решения с сортировкой, здесь не требуется ни сортировать исходный массив, ни создавать дополнительные массивы.

## 9. Что важно запомнить

1. Проверять нужно только делители длины массива.
2. Один циклический спуск означает, что блок можно повернуть в неубывающий порядок.
3. Проверка границ блоков гарантирует, что после их независимой сортировки весь массив будет отсортирован.
4. Ответ — сумма всех значений `k`, прошедших обе проверки.

Именно сочетание этих двух проверок позволяет решить задачу без сортировки и без использования дополнительной памяти, пропорциональной размеру массива.
