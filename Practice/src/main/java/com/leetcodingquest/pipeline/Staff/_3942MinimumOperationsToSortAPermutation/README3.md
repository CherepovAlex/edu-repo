# LeetCode 3942. Minimum Operations to Sort Permutation

> **Примечание преподавателя:** Привет, студенты! Сегодня мы разбираем задачу на алгоритмическое мышление и работу с циклическими структурами. Задача кажется простой, но содержит подвох в порядке применения операций. Мы разберем оптимальное решение за $O(N)$ времени.

## 📋 Описание задачи

Вам дан целочисленный массив `nums` длиной `n`, который является перестановкой чисел от `0` до `n - 1`.
Доступны две операции:
1. **Обратить весь массив (Reverse):** `[a, b, c]` $\to$ `[c, b, a]`.
2. **Повернуть влево на единицу (Left Shift):** `[a, b, c]` $\to$ `[b, c, a]`.

Необходимо найти **минимальное количество операций** для сортировки массива в возрастающем порядке `[0, 1, ..., n-1]`. Если это невозможно, вернуть `-1`.

### Примеры

**Пример 1:**
```text
Input:  nums = [0, 2, 1]
Output: 2
Explanation: 
1. Left Shift: [2, 1, 0]
2. Reverse:    [0, 1, 2] (Sorted)
```

**Пример 2:**
```text
Input:  nums = [1, 0, 2]
Output: 2
Explanation: 
1. Reverse:    [2, 0, 1]
2. Left Shift: [0, 1, 2] (Sorted)
```

**Пример 3:**
```text
Input:  nums = [2, 0, 1, 3]
Output: -1
Explanation: Impossible to sort.
```

### Ограничения
- $1 \le n == nums.length \le 10^5$
- $0 \le nums[i] \le n - 1$
- `nums` — перестановка чисел от $0$ до $n-1$.

## 💡 Теоретический анализ

### Ключевая идея
Любая последовательность операций "сдвиг" и "реверс" может быть сведена к одному из трех базовых сценариев, так как:
1. Два реверса подряд отменяют друг друга ($R(R(A)) = A$).
2. Сдвиги можно объединять.
3. Коммутативность ограничена, но множество достижимых состояний ограничено циклическими сдвигами исходного массива и его реверса.

Нам нужно проверить три возможных пути получения отсортированного массива `Target = [0, 1, ..., n-1]`:

1. **Только сдвиги:**
   Исходный массив `nums` уже является циклическим сдвигом `Target`.
   *Операции:* $k$ сдвигов.

2. **Сдвиги, затем Реверс:**
   Мы делаем $k$ сдвигов, получаем массив `Temp`, затем делаем реверс `Temp`, и он становится `Target`.
   Это эквивалентно условию: `Temp = Reverse(Target)`.
   То есть, `nums` должен быть циклическим сдвигом массива `ReversedTarget = [n-1, n-2, ..., 0]`.
   *Операции:* $k$ сдвигов + 1 реверс = $k + 1$.

3. **Реверс, затем Сдвиги:**
   Мы делаем реверс `nums`, получая `RevNums`, затем делаем $k$ сдвигов, и он становится `Target`.
   То есть, `RevNums` должен быть циклическим сдвигом `Target`.
   *Операции:* 1 реверс + $k$ сдвигов = $1 + k$.

### Алгоритм проверки циклического сдвига
Функция `getShifts(arr, target, n)` должна определить, является ли `arr` циклическим сдвигом `target`, и если да, то каково минимальное количество сдвигов влево.

1. Найти индекс элемента `target[0]` в массиве `arr`. Назовем его `pos`.
2. Проверить, совпадает ли последовательность элементов в `arr`, начиная с индекса `pos` (с учетом цикличности), с массивом `target`.
   - Условие: `arr[(pos + i) % n] == target[i]` для всех $0 \le i < n$.
3. Если проверка успешна, вернуть `pos` (количество сдвигов).
4. Если проверка провалена или элемент не найден, вернуть `-1`.

## 🛠️ Решение на Java

Ниже представлено полное решение с подробными комментариями к каждой строке.

```java
class Solution {
    /**
     * Вычисляет минимальное количество операций для сортировки перестановки.
     *
     * @param nums массив-перестановка от 0 до n-1
     * @return минимальное количество операций или -1, если невозможно
     */
    public int sortPermutation(int[] nums) {
        int n = nums.length;
        
        // Создаем эталонный отсортированный массив: [0, 1, 2, ..., n-1]
        int[] sorted = new int[n];
        // Создаем эталонный массив, являющийся реверсом отсортированного: [n-1, n-2, ..., 0]
        int[] reversedSorted = new int[n];
        
        for (int i = 0; i < n; i++) {
            sorted[i] = i;
            reversedSorted[i] = n - 1 - i;
        }
        
        // --- Вариант 1: Только сдвиги ---
        // Проверяем, можно ли получить sorted, просто сдвигая nums влево.
        // getShifts вернет количество сдвигов, если nums является циклическим сдвигом sorted.
        int k1 = getShifts(nums, sorted, n);
        
        // --- Вариант 2: Сдвиги, затем Реверс ---
        // Логика: S^k(nums) -> Reverse -> Sorted
        // Это означает, что S^k(nums) должен быть равен Reverse(Sorted).
        // Значит, nums должен быть циклическим сдвигом массива reversedSorted.
        // Количество операций: k сдвигов + 1 реверс.
        int k2 = getShifts(nums, reversedSorted, n);
        
        // --- Вариант 3: Реверс, затем Сдвиги ---
        // Логика: Reverse(nums) -> S^k -> Sorted
        // Это означает, что Reverse(nums) должен быть циклическим сдвигом sorted.
        // Сначала создаем реверсированную копию nums.
        int[] reversedNums = new int[n];
        for (int i = 0; i < n; i++) {
            reversedNums[i] = nums[n - 1 - i];
        }
        // Проверяем, сколько сдвигов нужно применить к reversedNums, чтобы получить sorted.
        int k3 = getShifts(reversedNums, sorted, n);
        
        // --- Вычисление минимума ---
        int minOps = Integer.MAX_VALUE;
        
        // Если Вариант 1 возможен, обновляем минимум
        if (k1 != -1) {
            minOps = Math.min(minOps, k1);
        }
        
        // Если Вариант 2 возможен, обновляем минимум (добавляем 1 операцию реверса)
        if (k2 != -1) {
            minOps = Math.min(minOps, k2 + 1);
        }
        
        // Если Вариант 3 возможен, обновляем минимум (добавляем 1 операцию реверса)
        if (k3 != -1) {
            minOps = Math.min(minOps, 1 + k3);
        }
        
        // Если ни один вариант не сработал, возвращаем -1
        return minOps == Integer.MAX_VALUE ? -1 : minOps;
    }
    
    /**
     * Проверяет, является ли массив arr циклическим сдвигом массива target.
     * Если да, возвращает минимальное количество сдвигов влево, необходимых для совпадения.
     * Если нет, возвращает -1.
     *
     * @param arr    исходный массив
     * @param target целевой массив
     * @param n      длина массивов
     * @return количество сдвигов или -1
     */
    private int getShifts(int[] arr, int[] target, int n) {
        // Находим позицию первого элемента целевого массива в исходном массиве.
        // Так как это перестановка, элемент target[0] встречается ровно один раз.
        int pos = -1;
        for (int i = 0; i < n; i++) {
            if (arr[i] == target[0]) {
                pos = i;
                break;
            }
        }
        
        // Если элемент не найден (теоретически невозможно для корректной перестановки), возвращаем ошибку
        if (pos == -1) {
            return -1;
        }
        
        // Проверяем, совпадает ли вся структура arr относительно найденной позиции с target.
        // Мы идем по arr начиная с индекса pos по кругу и сравниваем с target[i].
        for (int i = 0; i < n; i++) {
            // Вычисляем индекс в arr с учетом циклического смещения
            int currentIndex = (pos + i) % n;
            
            // Если элемент не совпадает, значит arr не является циклическим сдвигом target
            if (arr[currentIndex] != target[i]) {
                return -1;
            }
        }
        
        // Если проверка прошла успешно, количество сдвигов влево, чтобы элемент target[0]
        // оказался на нулевой позиции, равно индексу pos.
        // Пример: arr=[2, 0, 1], target=[0, 1, 2]. pos=1.
        // Сдвиг влево на 1: [0, 1, 2]. Совпало. Возвращаем 1.
        return pos;
    }
}
```

## 🧪 Пошаговое выполнение на примерах

### Пример 1: `nums = [0, 2, 1]`
`n = 3`.
`sorted = [0, 1, 2]`
`reversedSorted = [2, 1, 0]`

1. **Вариант 1 (`k1`):** `getShifts([0, 2, 1], [0, 1, 2])`
   - `target[0] = 0`. Находим `0` в `nums` по индексу `0`. `pos = 0`.
   - Проверка:
     - `i=0`: `arr[(0+0)%3] = arr[0] = 0`. `target[0]=0`. OK.
     - `i=1`: `arr[(0+1)%3] = arr[1] = 2`. `target[1]=1`. **Не OK**.
   - Результат: `k1 = -1`.

2. **Вариант 2 (`k2`):** `getShifts([0, 2, 1], [2, 1, 0])`
   - `target[0] = 2`. Находим `2` в `nums` по индексу `1`. `pos = 1`.
   - Проверка:
     - `i=0`: `arr[(1+0)%3] = arr[1] = 2`. `target[0]=2`. OK.
     - `i=1`: `arr[(1+1)%3] = arr[2] = 1`. `target[1]=1`. OK.
     - `i=2`: `arr[(1+2)%3] = arr[0] = 0`. `target[2]=0`. OK.
   - Результат: `k2 = 1`.
   - Стоимость: `k2 + 1 = 2`.

3. **Вариант 3 (`k3`):** `reversedNums = [1, 2, 0]`. `getShifts([1, 2, 0], [0, 1, 2])`
   - `target[0] = 0`. Находим `0` в `reversedNums` по индексу `2`. `pos = 2`.
   - Проверка:
     - `i=0`: `arr[(2+0)%3] = arr[2] = 0`. `target[0]=0`. OK.
     - `i=1`: `arr[(2+1)%3] = arr[0] = 1`. `target[1]=1`. OK.
     - `i=2`: `arr[(2+2)%3] = arr[1] = 2`. `target[2]=2`. OK.
   - Результат: `k3 = 2`.
   - Стоимость: `1 + k3 = 3`.

**Итог:** `min(-1 игнорируется, 2, 3) = 2`.
Ответ: **2**.

### Пример 2: `nums = [1, 0, 2]`
`n = 3`.

1. **Вариант 1 (`k1`):** `getShifts([1, 0, 2], [0, 1, 2])`
   - `target[0] = 0`. `pos = 1`.
   - Проверка: `arr[1]=0` (OK), `arr[2]=2` (Expected 1, Fail).
   - `k1 = -1`.

2. **Вариант 2 (`k2`):** `getShifts([1, 0, 2], [2, 1, 0])`
   - `target[0] = 2`. `pos = 2`.
   - Проверка: `arr[2]=2` (OK), `arr[0]=1` (OK), `arr[1]=0` (OK).
   - `k2 = 2`.
   - Стоимость: `2 + 1 = 3`.

3. **Вариант 3 (`k3`):** `reversedNums = [2, 0, 1]`. `getShifts([2, 0, 1], [0, 1, 2])`
   - `target[0] = 0`. `pos = 1`.
   - Проверка: `arr[1]=0` (OK), `arr[2]=1` (OK), `arr[0]=2` (OK).
   - `k3 = 1`.
   - Стоимость: `1 + 1 = 2`.

**Итог:** `min(inf, 3, 2) = 2`.
Ответ: **2**.

### Пример 3: `nums = [2, 0, 1, 3]`
`n = 4`.

1. **Вариант 1 (`k1`):** `getShifts([2, 0, 1, 3], [0, 1, 2, 3])`
   - `target[0]=0`. `pos=1`.
   - Проверка: `arr[1]=0` (OK), `arr[2]=1` (OK), `arr[3]=3` (Expected 2, Fail).
   - `k1 = -1`.

2. **Вариант 2 (`k2`):** `getShifts([2, 0, 1, 3], [3, 2, 1, 0])`
   - `target[0]=3`. `pos=3`.
   - Проверка: `arr[3]=3` (OK), `arr[0]=2` (OK), `arr[1]=0` (Expected 1, Fail).
   - `k2 = -1`.

3. **Вариант 3 (`k3`):** `reversedNums = [3, 1, 0, 2]`. `getShifts([3, 1, 0, 2], [0, 1, 2, 3])`
   - `target[0]=0`. `pos=2`.
   - Проверка: `arr[2]=0` (OK), `arr[3]=2` (Expected 1, Fail).
   - `k3 = -1`.

**Итог:** Все варианты `false`.
Ответ: **-1**.

## 📊 Сложность

### Временная сложность: $O(N)$
1. Создание массивов `sorted` и `reversedSorted`: $O(N)$.
3. Создание `reversedNums`: $O(N)$.
4. Вызов `getShifts` три раза:
   - Поиск позиции: $O(N)$.
   - Проверка всех элементов: $O(N)$.
   - Всего за вызов: $O(N)$.
   - Три вызова: $3 \times O(N) = O(N)$.
**Итоговая сложность:** $O(N)$.

### Пространственная сложность: $O(N)$
- Мы создаем массивы `sorted`, `reversedSorted` и `reversedNums`, каждый размером $N$.
- **Итоговая сложность:** $O(N)$.

*(Примечание: Можно оптимизировать пространство до $O(1)$, не создавая новые массивы, а вычисляя значения "на лету", но для читаемости и ясности решения создание массивов предпочтительнее и соответствует ограничениям $N=10^5$).*
