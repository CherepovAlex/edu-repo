# LeetCode 3942. Минимальное количество операций для сортировки перестановки

> Подробный разбор задачи с оптимальным решением на Java, построчными комментариями и пошаговым разбором примеров. Материал оформлен как README для публикации на GitHub и чтения в IntelliJ IDEA.

## 📋 Условие задачи

Дан целочисленный массив `nums` длиной `n`, где `nums` — перестановка целых чисел от `0` до `n - 1`.

Разрешены только две операции:

1. **Обратить весь массив** (реверс).
2. **Повернуть влево на единицу**: переместить первый элемент в конец массива, остальные сдвинуть на одну позицию влево.

Верните целое число — минимальное количество операций, необходимых для сортировки массива в возрастающем порядке. Если отсортировать массив, используя только эти операции, невозможно, верните `-1`.

### Примеры

**Пример 1:**
```
Вход:  nums = [0, 2, 1]
Выход: 2
Пояснение:
  Поворот влево на один шаг: [2, 1, 0]
  Реверс массива:            [0, 1, 2]
  Массив сортируется за 2 операции — это минимум.
```

**Пример 2:**
```
Вход:  nums = [1, 0, 2]
Выход: 2
Пояснение:
  Перевернуть массив:        [2, 0, 1]
  Поворот влево на один шаг: [0, 1, 2]
  Массив сортируется за 2 операции — это минимум.
```

**Пример 3:**
```
Вход:  nums = [2, 0, 1, 3]
Выход: -1
Пояснение:
  Невозможно получить [0, 1, 2, 3] только этими операциями.
```

### Ограничения

- `1 <= n == nums.length <= 10^5`
- `0 <= nums[i] <= n - 1`
- `nums` — перестановка целых чисел от `0` до `n - 1`

## 💡 Идея решения

Ключ к задаче — понять суть двух операций:

- **Левый сдвиг** меняет только "начальную позицию" массива (точку старта обхода).
- **Реверс** меняет только "направление обхода".

Следовательно, любой массив, который можно получить из исходного комбинацией этих операций, — это либо:

1. Исходный массив, который после нескольких левых сдвигов становится **возрастающей последовательностью** `0, 1, ..., n-1`.
2. Исходный массив, который после нескольких левых сдвигов становится **убывающей последовательностью** `n-1, n-2, ..., 0`, которую затем одним реверсом превращаем в возрастающую.

Иными словами, исходный массив `nums` в циклическом смысле должен **изначально** быть:

- либо циклическим сдвигом возрастающей последовательности,
- либо циклическим сдвигом убывающей последовательности.

Иначе ответ сразу `-1` — никакое число операций не поможет.

### Алгоритм

1. Находим позицию `0` (`zeroIndex`) и позицию `n-1` (`maxIndex`).
2. Проверяем возрастание: обходя массив по кругу, начиная с `zeroIndex`, получаем ли ровно `0, 1, ..., n-1`.
3. Проверяем убывание: обходя массив по кругу, начиная с `maxIndex`, получаем ли ровно `n-1, n-2, ..., 0`.
4. Если оба условия ложны — возвращаем `-1`.
5. Иначе вычисляем стоимость двух стратегий для каждого подходящего случая и берём минимум.

### Сложность

| Показатель | Значение |
|---|---|
| Время | **O(n)** — один проход на поиск позиций, ещё по одному на проверку каждого случая |
| Память | **O(1)** — только несколько целочисленных переменных |

---

## 🧠 Как считаются операции

Обозначим:
- `k` — сколько раз нужно сделать левый сдвиг, чтобы получить нужный порядок (возрастающий или убывающий);
- `n` — длина массива.

**Стратегия A. Только сдвиги (для возрастания):**
```
k операций
```

**Стратегия B. Реверс + обратный сдвиг + реверс (для возрастания):**
Если проще крутить в другую сторону, делаем `реверс → (n-k) сдвигов → реверс`:
```
(n - k) + 2 операции
```

**Стратегия C. Сдвиги + реверс (для убывания):**
```
k + 1 операция
```

**Стратегия D. Реверс + сдвиги (для убывания):**
```
(n - k) + 1 операция
```

Из всех допустимых стратегий берём минимум.

## 💻 Код решения на Java

```java
class Solution {
    public int minOperations(int[] nums) {
        int n = nums.length;                                          // длина массива

        if (n == 1) {                                                 // массив из одного элемента уже отсортирован
            return 0;                                                 // операций не нужно
        }

        if (n == 2) {                                                 // особый случай длины 2
            if (nums[0] == 0 && nums[1] == 1) {                       // уже отсортирован
                return 0;                                             // 0 операций
            }                                                         // иначе это [1,0]
            return 1;                                                 // один реверс или один сдвиг
        }

        int zeroIndex = -1, maxIndex = -1;                            // позиции 0 и n-1
        for (int i = 0; i < n; i++) {                                 // один проход по массиву
            if (nums[i] == 0) {                                       // нашли 0
                zeroIndex = i;                                        // запоминаем индекс
            } else if (nums[i] == n - 1) {                            // нашли максимум n-1
                maxIndex = i;                                         // запоминаем индекс
            }
        }

        boolean canInc = true;                                        // можно ли сдвигами получить возрастание
        for (int i = 0, j = zeroIndex; i < n; i++, j = (j + 1) % n) { // идём по кругу от позиции 0
            if (nums[j] != i) {                                       // на i-м шаге ожидаем значение i
                canInc = false;                                       // не совпало — возрастание невозможно
                break;                                                // досрочно выходим
            }
        }

        boolean canDec = true;                                        // можно ли сдвигами получить убывание
        for (int i = 0, j = maxIndex; i < n; i++, j = (j + 1) % n) {  // идём по кругу от позиции n-1
            if (nums[j] != n - 1 - i) {                               // ожидаем n-1, n-2, ...
                canDec = false;                                       // не совпало — убывание невозможно
                break;                                                // досрочно выходим
            }
        }

        int ans = Integer.MAX_VALUE;                                  // минимум операций

        if (canInc) {                                                 // случай 1: сдвигами получаем возрастание
            int cost1 = zeroIndex;                                    // просто left-rotate zeroIndex раз
            int cost2 = n - zeroIndex + 2;                            // реверс + сдвиг + реверс = (n-zeroIndex) + 2
            ans = Math.min(ans, Math.min(cost1, cost2));              // берём меньшее
        }

        if (canDec) {                                                 // случай 2: сдвигами получаем убывание, затем реверс
            int cost1 = maxIndex + 1;                                 // сдвиг maxIndex раз до убывания + 1 реверс
            int cost2 = n - maxIndex + 1;                             // сначала реверс, затем сдвиг до убывания + реверс
            ans = Math.min(ans, Math.min(cost1, cost2));              // берём меньшее
        }

        return ans == Integer.MAX_VALUE ? -1 : ans;                   // если ни один случай не подошёл — -1, иначе ans
    }
}
```

## 🔍 Пошаговый разбор примеров

### Пример 1: `nums = [0, 2, 1]`, `n = 3`

**Позиции:** `zeroIndex = 0` (значение `0` на индексе `0`), `maxIndex = 1` (значение `2` на индексе `1`).

**Проверка возрастания:** идём от `zeroIndex = 0`:

| Шаг | Индекс `j` | `nums[j]` | Ожидали | Совпало? |
|---|---|---|---|---|
| 0 | 0 | 0 | 0 | ✅ |
| 1 | 1 | 2 | 1 | ❌ |

→ `canInc = false`.

**Проверка убывания:** идём от `maxIndex = 1`:

| Шаг | Индекс `j` | `nums[j]` | Ожидали | Совпало? |
|---|---|---|---|---|
| 0 | 1 | 2 | 2 | ✅ |
| 1 | 2 | 1 | 1 | ✅ |
| 2 | 0 | 0 | 0 | ✅ |

→ `canDec = true`.

**Вычисления:**
- `cost1 = maxIndex + 1 = 2`: сдвиг 1 раз → `[2,1,0]` (убывание), затем реверс → `[0,1,2]`. Итого 2 операции ✅
- `cost2 = n - maxIndex + 1 = 3 - 1 + 1 = 3`: сначала реверс → `[1,2,0]`, затем сдвиг до убывания, затем реверс — 3 операции (хуже)
- `ans = min(2, 3) = 2`

**Ответ: 2** — совпадает с примером.

---

### Пример 2: `nums = [1, 0, 2]`, `n = 3`

**Позиции:** `zeroIndex = 1` (значение `0` на индексе `1`), `maxIndex = 2` (значение `2` на индексе `2`).

**Проверка возрастания:** идём от `zeroIndex = 1`:

| Шаг | Индекс `j` | `nums[j]` | Ожидали | Совпало? |
|---|---|---|---|---|
| 0 | 1 | 0 | 0 | ✅ |
| 1 | 2 | 2 | 1 | ❌ |

→ `canInc = false`.

**Проверка убывания:** идём от `maxIndex = 2`:

| Шаг | Индекс `j` | `nums[j]` | Ожидали | Совпало? |
|---|---|---|---|---|
| 0 | 2 | 2 | 2 | ✅ |
| 1 | 0 | 1 | 1 | ✅ |
| 2 | 1 | 0 | 0 | ✅ |

→ `canDec = true`.

**Вычисления:**
- `cost1 = maxIndex + 1 = 3`: сдвиг 2 раза + реверс = 3
- `cost2 = n - maxIndex + 1 = 3 - 2 + 1 = 2`: реверс → `[2,0,1]`, затем левый сдвиг 1 раз → `[0,1,2]`. Итого 2 операции ✅
- `ans = min(3, 2) = 2`

**Ответ: 2** — совпадает с примером.

**Позиции:** `zeroIndex = 1` (значение `0` на индексе `1`), `maxIndex = 3` (значение `3` на индексе `3`).

**Проверка возрастания:** идём от `zeroIndex = 1`:

|---|---|---|---|---|

| 1 | 2 | 1 | 1 | ✅ |

→ `canInc = false`.

| 0 | 3 | 3 | 3 | ✅ |

## ✅ Обоснование корректности

Для `n ≥ 3` перестановка, которую можно отсортировать комбинацией "левый сдвиг + реверс", обязана иметь один из двух видов:

1. **Циклический сдвиг возрастающей последовательности**: обходя массив по кругу с некоторой позиции, получаем ровно `0, 1, ..., n-1`.
2. **Циклический сдвиг убывающей последовательности**: обходя массив по кругу с некоторой позиции, получаем ровно `n-1, n-2, ..., 0`.

Это следует из того, что левый сдвиг меняет только точку старта, а реверс — только направление обхода. Если исходный массив не удовлетворяет ни одному условию, никакое число операций не приведёт его к отсортированному виду.

Подсчёт операций корректен, потому что:
- левый сдвиг на `k` позиций стоит `k`;
- реверс стоит `1`;
- "обратный сдвиг" (в противоположную сторону) реализуется как `реверс + сдвиг + реверс` и стоит на `2` больше прямого;
- минимум по всем допустимым стратегиям — и есть оптимальный ответ.
