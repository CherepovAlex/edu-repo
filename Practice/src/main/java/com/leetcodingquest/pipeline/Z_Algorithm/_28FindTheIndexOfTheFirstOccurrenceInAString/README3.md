# LeetCode 28: Find the Index of the First Occurrence in a String

## Описание задачи

**Название:** Найти индекс первого вхождения в строку  
**Номер задачи на LeetCode:** 28  
**Уровень сложности:** Easy

Даны две строки `needle` и `haystack`, верните индекс первого вхождения `needle` в `haystack` или `-1`, если `needle` не является частью `haystack`.

### Примеры

**Пример 1:**
```
Входные данные: haystack = "sadbutsad", needle = "sad"
Выходные данные: 0
Пояснение: "sad" встречается в позициях 0 и 6. Первое вхождение находится в позиции 0, поэтому мы возвращаем 0.
```

**Пример 2:**
```
Входные данные: haystack = "leetcode", needle = "leeto"
Выходные данные: -1
Пояснение: "leeto" не встречается в "leetcode", поэтому мы возвращаем -1.
```

### Ограничения

*   $1 \le \text{haystack.length}, \text{needle.length} \le 10^4$
*   `haystack` и `needle` состоят только из строчных букв английского алфавита.

---

## Решение на Java

В данном решении используется встроенный метод Java `String.indexOf()`. Это стандартный, наиболее читаемый и эффективный способ решения задачи в промышленной разработке на Java, так как реализация внутри JDK (JVM) оптимизирована на уровне аппаратных инструкций и использует эффективные алгоритмы поиска.

```java
public class Solution1 {

    /**
     * Метод для поиска первого вхождения подстроки needle в строку haystack.
     *
     * @param haystack Строка, в которой производится поиск.
     * @param needle   Подстрока, которую нужно найти.
     * @return Индекс первого вхождения needle в haystack, или -1, если не найдено.
     */
    public int strStr(String haystack, String needle) {
        // Проверяем, не пуста ли needle.
        // Согласно математическому определению, пустая строка содержится в любой строке на позиции 0.
        // Хотя в ограничениях задачи указано needle.length >= 1, эта проверка делает код надежным.
        if (needle.isEmpty()) {
            return 0;
        }

        // Используем встроенный метод indexOf класса String.
        // Этот метод ищет первое вхождение needle в haystack.
        // Внутри JDK реализация оптимизирована (использует проверки символов и эффективные циклы),
        // что делает её быстрой на практике для заданных ограничений.
        int index = haystack.indexOf(needle);

        // indexOf возвращает -1, если подстрока не найдена,
        // что полностью соответствует требованиям задачи.
        return index;
    }

    public static void main(String[] args) {
        // Создаем экземпляр класса Solution1 для вызова метода
        Solution1 solution = new Solution1();

        // --- Пример 1 ---
        String haystack1 = "sadbutsad";
        String needle1 = "sad";
        // Вызываем метод и выводим результат
        // Ожидаемый вывод: 0
        System.out.println("Пример 1: " + solution.strStr(haystack1, needle1));

        // --- Пример 2 ---
        String haystack2 = "leetcode";
        String needle2 = "leeto";
        // Вызываем метод и выводим результат
        // Ожидаемый вывод: -1
        System.out.println("Пример 2: " + solution.strStr(haystack2, needle2));

        // --- Пример 3 (Дополнительный для проверки) ---
        String haystack3 = "hello";
        String needle3 = "ll";
        // Вызываем метод и выводим результат
        // Ожидаемый вывод: 2
        System.out.println("Пример 3: " + solution.strStr(haystack3, needle3));
    }
}
```

## Пошаговое объяснение решения

### 1. Анализ ограничений
*   Длина строк до $10^4$. Это означает, что наивный алгоритм $O(N \cdot M)$ может выполнить до $10^8$ операций в худшем случае. Современные JVM и метод `indexOf` справляются с этим объемом данных за доли секунды благодаря оптимизациям.
*   Строки состоят только из строчных букв английского алфавита, что упрощает сравнение (не нужно учитывать регистр или юникод-специфику в данном контексте).

### 2. Логика метода `strStr`

**Строка 1:** `if (needle.isEmpty()) { return 0; }`
*   **Действие:** Проверяет, является ли искомая подстрока пустой.
*   **Обоснование:** Пустая строка считается подстрокой любой строки и формально находится на позиции 0. Это edge-case обработка, хотя по условию задачи `needle` всегда не пустая.

**Строка 2:** `int index = haystack.indexOf(needle);`
*   **Действие:** Вызывает встроенный метод поиска подстроки.
*   **Внутренняя логика (упрощенно):**
    1.  Метод начинает сканирование `haystack` с индекса 0.
    2.  На каждой позиции проверяется, совпадает ли подстрока длины `needle.length` с искомой `needle`.
    3.  Если совпадение найдено, возвращается текущий индекс.
    4.  Если нет, сканирование продолжается со следующего индекса.
    5.  Если дойдя до конца строки совпадений не найдено, возвращается `-1`.
*   **Оптимальность:** В JDK реализация `indexOf` использует оптимизации, такие как предварительная проверка первого и последнего символов, что значительно ускоряет поиск на практике по сравнению с чистым наивным перебором.

**Строка 3:** `return index;`
*   **Действие:** Возвращает результат поиска.

## Детальный разбор примеров

### Пример 1: `haystack = "sadbutsad"`, `needle = "sad"`

1.  **Инициализация:** `haystack = "sadbutsad"`, `needle = "sad"`.
2.  **Проверка:** `needle` не пустой.
3.  **Вызов `indexOf`:**
    *   Начинаем сравнение с индекса `0`.
    *   Берем подстроку `haystack[0..2]` (длина 3), которая равна `"sad"`.
    *   Сравниваем с `needle` (`"sad"`).
    *   Символы совпадают:
        *   `haystack[0]` ('s') == `needle[0]` ('s')
        *   `haystack[1]` ('a') == `needle[1]` ('a')
        *   `haystack[2]` ('d') == `needle[2]` ('d')
    *   **Результат:** Совпадение найдено на индексе `0`.
4.  **Возврат:** Метод возвращает `0`.

### Пример 2: `haystack = "leetcode"`, `needle = "leeto"`

1.  **Инициализация:** `haystack = "leetcode"`, `needle = "leeto"`.
2.  **Проверка:** `needle` не пустой.
3.  **Вызов `indexOf`:**
    *   **Индекс 0:** Подстрока `"leetc"` vs `"leeto"`.
        *   'l'=='l', 'e'=='e', 'e'=='e', 't'=='t', но 'c'!='o'. Не совпадает.
    *   **Индекс 1:** Подстрока `"eetco"` vs `"leeto"`.
        *   'e'!='l'. Не совпадает.
    *   **Индекс 2:** Подстрока `"etcod"` vs `"leeto"`.
        *   'e'!='l'. Не совпадает.
    *   **Индекс 3:** Подстрока `"tcode"` vs `"leeto"`.
        *   't'!='l'. Не совпадает.
    *   **Индекс 4:** Оставшаяся часть `"code"` имеет длину 4, что меньше длины `needle` (5). Дальнейший поиск невозможен.
    *   **Результат:** Совпадений не найдено.
4.  **Возврат:** Метод возвращает `-1`.

### Пример 3 (Дополнительный): `haystack = "hello"`, `needle = "ll"`

1.  **Инициализация:** `haystack = "hello"`, `needle = "ll"`.
2.  **Вызов `indexOf`:**
    *   **Индекс 0:** Подстрока `"he"` vs `"ll"`. 'h'!='l'. Не совпадает.
    *   **Индекс 1:** Подстрока `"el"` vs `"ll"`. 'e'!='l'. Не совпадает.
    *   **Индекс 2:** Подстрока `"ll"` vs `"ll"`.
        *   `haystack[2]` ('l') == `needle[0]` ('l')
        *   `haystack[3]` ('l') == `needle[1]` ('l')
    *   **Результат:** Совпадение найдено на индексе `2`.
3.  **Возврат:** Метод возвращает `2`.

## Анализ сложности

### Временная сложность
*   **Практическая:** $O(N)$ или $O(N \cdot M)$ в худшем случае для наивной части, но благодаря оптимизациям в JDK (`indexOf`) на реальных данных работает значительно быстрее. Для строк длиной $10^4$ время выполнения составляет микросекунды.
*   **Теоретическая (если бы писали вручную):** Наивный подход $O(N \cdot M)$. Алгоритм Кнута-Морриса-Пратта (KMP) обеспечивает гарантированную $O(N + M)$. Однако использование `indexOf` предпочтительнее в Java, так как оно написано на нативном уровне и использует аппаратные ускорения.

### Пространственная сложность
*   $O(1)$ — дополнительная память не используется, так как мы не создаем новых объектов строк или массивов. Мы работаем с исходными данными.

## Заключение

Использование `String.indexOf()` является **best practice** для данной задачи в Java. Оно обеспечивает:
1.  **Читаемость:** Код понятен любому разработчику.
2.  **Надежность:** Используется стандартная библиотека, протестированная на миллионах сценариев.
3.  **Производительность:** Оптимизирована внутри JVM.

Для академических целей или специфических требований собеседований (например, "реализуй KMP вручную") можно написать алгоритм поиска с использованием префикс-функции, но в реальной разработке этот подход избыточен.
