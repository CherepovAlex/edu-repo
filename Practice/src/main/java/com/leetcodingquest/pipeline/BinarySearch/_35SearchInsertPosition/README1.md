# LeetCode № 35 — Поиск позиции вставки (Search Insert Position)

## 1. Условие задачи

Дан отсортированный массив различных целых чисел `nums` и целевое значение `target`.

Необходимо вернуть индекс, если целевое значение найдено в массиве. Если значение отсутствует, необходимо вернуть индекс, на который его следовало бы вставить, чтобы массив остался отсортированным по возрастанию.

**Требование:** алгоритм должен иметь временную сложность `O(log n)`.

### Пример 1

**Входные данные:**

```text
nums = [1, 3, 5, 6]
target = 5
```

**Результат:**

```text
2
```

**Объяснение:** число `5` находится по индексу `2`.

### Пример 2

**Входные данные:**

```text
nums = [1, 3, 5, 6]
target = 2
```

**Результат:**

```text
1
```

**Объяснение:** число `2` отсутствует. Его необходимо вставить между числами `1` и `3`, то есть по индексу `1`.

### Пример 3

**Входные данные:**

```text
nums = [1, 3, 5, 6]
target = 7
```

**Результат:**

```text
4
```

**Объяснение:** число `7` больше всех элементов массива, поэтому его необходимо вставить в конец. Индекс вставки равен `4`.

## 2. Ограничения

- `1 <= nums.length <= 10^4`
- `-10^4 <= nums[i] <= 10^4`
- Массив `nums` отсортирован по возрастанию.
- Все элементы массива различны.
- `-10^4 <= target <= 10^4`

## 3. Что такое индекс массива в Java?

В Java индексация массива начинается с нуля.

Для массива:

```java
int[] nums = {1, 3, 5, 6};
```

Индексы распределяются следующим образом:

| Индекс | Значение |
|---:|---:|
| 0 | 1 |
| 1 | 3 |
| 2 | 5 |
| 3 | 6 |

Количество элементов массива равно `4`, но индекс последнего элемента равен `3`.

Это объясняется тем, что последний индекс вычисляется по формуле:

```java
nums.length - 1
```

При этом индекс `4` можно использовать как позицию вставки после последнего элемента.

Например, после вставки числа `7` массив будет выглядеть так:

```text
[1, 3, 5, 6, 7]
```

Число `7` окажется по индексу `4`.

## 4. Какой алгоритм использовать?

Для решения задачи используется **бинарный поиск (Binary Search)**.

Поскольку массив уже отсортирован, необязательно проверять каждый элемент последовательно. Можно сравнивать целевое значение со средним элементом текущего диапазона поиска и каждый раз исключать примерно половину элементов.

### Линейный поиск

Линейный поиск последовательно проверяет элементы массива.

В худшем случае придётся проверить все `n` элементов.

Временная сложность:

```text
O(n)
```

Это не соответствует требованию задачи.

### Бинарный поиск

Бинарный поиск на каждом шаге сокращает диапазон поиска примерно вдвое.

Временная сложность:

```text
O(log n)
```

Поэтому бинарный поиск является подходящим решением задачи.

## 5. Идея алгоритма

Для реализации понадобятся три переменные:

- `left` — индекс левой границы диапазона поиска.
- `right` — индекс правой границы диапазона поиска.
- `mid` — индекс среднего элемента текущего диапазона.

В начале поиска весь массив является диапазоном поиска:

```java
left = 0;
right = nums.length - 1;
```

Для массива `[1, 3, 5, 6]` начальные значения будут такими:

```text
left = 0
right = 3
```

Вычисляем середину диапазона:

```java
int mid = left + (right - left) / 2;
```

Получаем:

```text
mid = 0 + (3 - 0) / 2
mid = 1
```

Средний элемент:

```java
nums[mid] = nums[1] = 3;
```

Далее сравниваем его с `target`.

### Случай 1. Элемент найден

Если:

```java
nums[mid] == target
```

возвращаем индекс:

```java
return mid;
```

### Случай 2. Средний элемент меньше цели

Если:

```java
nums[mid] < target
```

целевое значение может находиться правее среднего элемента.

Поэтому сдвигаем левую границу:

```java
left = mid + 1;
```

Сам элемент с индексом `mid` больше проверять не нужно, поскольку его значение уже меньше `target`.

### Случай 3. Средний элемент больше цели

Если:

```java
nums[mid] > target
```

целевое значение может находиться левее среднего элемента.

Поэтому сдвигаем правую границу:

```java
right = mid - 1;
```

### Случай 4. Элемент не найден

Когда левая граница становится больше правой:

```java
left > right
```

диапазон поиска становится пустым.

В этот момент `left` указывает на позицию, куда необходимо вставить `target`.

Поэтому в конце метода возвращаем:

```java
return left;
```

**Ключевая особенность задачи:** если элемент не найден, нужно вернуть `left`, а не `-1`.

## 6. Полное решение на Java с комментариями к каждой строке

```java
public class Solution1 {

    public int searchInsert(int[] nums, int target) {
        // Создаём переменную left.
        // Она хранит индекс левой границы поиска.
        // Изначально поиск начинается с первого элемента.
        int left = 0;

        // Создаём переменную right.
        // Она хранит индекс правой границы поиска.
        // Последний индекс равен длине массива минус один.
        int right = nums.length - 1;

        // Продолжаем поиск, пока диапазон не стал пустым.
        // Если left станет больше right, цикл завершится.
        while (left <= right) {

            // Вычисляем индекс среднего элемента диапазона.
            // Такая формула уменьшает риск переполнения int.
            int mid = left + (right - left) / 2;

            // Сравниваем средний элемент с целевым значением.
            // Если значения равны, элемент найден.
            if (nums[mid] == target) {

                // Возвращаем индекс найденного элемента.
                return mid;
            }

            // Проверяем, меньше ли средний элемент цели.
            if (nums[mid] < target) {

                // Цель может находиться только правее mid.
                // Исключаем mid и все элементы левее него.
                left = mid + 1;

            } else {

                // Если предыдущие условия не сработали,
                // средний элемент больше целевого значения.
                // Исключаем mid и все элементы правее него.
                right = mid - 1;
            }
        }

        // Элемент не найден.
        // left указывает на правильную позицию вставки.
        return left;
    }

    public static void main(String[] args) {

        // Создаём объект класса Solution1.
        // Он нужен для вызова нестатического метода searchInsert.
        Solution1 solution = new Solution1();

        // Пример 1.
        // Целевое значение присутствует в массиве.
        int[] nums1 = {1, 3, 5, 6};
        int target1 = 5;

        // Вызываем метод и выводим результат.
        // Ожидаемый результат: 2.
        System.out.println(solution.searchInsert(nums1, target1));

        // Пример 2.
        // Целевое значение нужно вставить в середину массива.
        int[] nums2 = {1, 3, 5, 6};
        int target2 = 2;

        // Ожидаемый результат: 1.
        System.out.println(solution.searchInsert(nums2, target2));

        // Пример 3.
        // Целевое значение нужно вставить в конец массива.
        int[] nums3 = {1, 3, 5, 6};
        int target3 = 7;

        // Ожидаемый результат: 4.
        System.out.println(solution.searchInsert(nums3, target3));
    }
}
```

### Результат выполнения программы

```text
2
1
4
```

## 7. Подробное объяснение кода

### 7.1. Объявление класса

```java
public class Solution1 {
```

Объявляем публичный класс `Solution1`.

В Java код методов размещается внутри классов.

Имя публичного класса должно совпадать с именем файла. Если класс называется `Solution1`, файл следует назвать `Solution1.java`.

На LeetCode имя класса обычно должно быть `Solution`.

### 7.2. Объявление метода

```java
public int searchInsert(int[] nums, int target) {
```

Разберём объявление по частям:

- `public` — метод доступен из других классов.
- `int` — метод возвращает целое число.
- `searchInsert` — имя метода.
- `int[] nums` — отсортированный массив целых чисел.
- `int target` — целевое число, которое необходимо найти или вставить.

Метод возвращает индекс, поэтому тип результата — `int`.

### 7.3. Левая граница

```java
int left = 0;
```

Создаём переменную, указывающую на начало диапазона поиска.

Изначально мы не знаем, где находится целевое число, поэтому рассматриваем весь массив.

### 7.4. Правая граница

```java
int right = nums.length - 1;
```

`nums.length` возвращает количество элементов.

Для массива:

```java
int[] nums = {1, 3, 5, 6};
```

значение `nums.length` равно `4`.

Следовательно:

```java
right = 4 - 1;
right = 3;
```

Правая граница указывает на последний элемент массива.

### 7.5. Условие цикла

```java
while (left <= right) {
```

Цикл выполняется, пока диапазон поиска содержит хотя бы один индекс.

Например:

```text
left = 1
right = 3
```

Условие истинно, потому что `1 <= 3`.

Но если:

```text
left = 4
right = 3
```

условие ложно, потому что `4 <= 3` — неверно.

В таком случае цикл прекращается.

### 7.6. Вычисление середины

```java
int mid = left + (right - left) / 2;
```

Переменная `mid` хранит индекс среднего элемента текущего диапазона.

Деление целых чисел в Java отбрасывает дробную часть.

Например:

```java
int mid = (0 + 3) / 2;
```

Результат:

```text
mid = 1
```

Используемая в решении формула:

```java
left + (right - left) / 2
```

предпочтительнее выражения `(left + right) / 2`, поскольку снижает риск переполнения `int` при больших значениях границ.

### 7.7. Проверка равенства

```java
if (nums[mid] == target) {
    return mid;
}
```

Обращаемся к элементу массива по индексу `mid`.

Если его значение совпадает с `target`, возвращаем индекс.

Оператор `return` немедленно завершает выполнение метода.

### 7.8. Проверка левой части диапазона

```java
if (nums[mid] < target) {
    left = mid + 1;
}
```

Если средний элемент меньше целевого значения, то все элементы слева от него также меньше `target`, поскольку массив отсортирован по возрастанию.

Поэтому продолжать поиск слева нет смысла.

Переносим левую границу на следующий индекс после `mid`.

### 7.9. Проверка правой части диапазона

```java
else {
    right = mid - 1;
}
```

Если элемент не равен `target` и при этом не меньше него, значит, он больше `target`.

В таком случае целевое значение или его позиция вставки находятся левее.

Сдвигаем правую границу на индекс перед `mid`.

### 7.10. Возвращение позиции вставки

```java
return left;
```

Эта строка выполняется только в том случае, если целевое значение не было найдено.

После завершения цикла:

```text
left > right
```

При этом `left` указывает на первую позицию, на которой целевое значение может находиться в отсортированном массиве.

Это справедливо для вставки в начало, середину и конец массива.

## 8. Пошаговый разбор примера № 1

**Входные данные:**

```java
nums = [1, 3, 5, 6]
target = 5
```

Необходимо найти число `5`.

### Шаг 1. Инициализация

```java
left = 0;
right = 3;
```

Текущий диапазон включает весь массив.

### Шаг 2. Вычисляем середину

```java
mid = left + (right - left) / 2;
mid = 0 + (3 - 0) / 2;
mid = 1;
```

Получаем:

```java
nums[mid] = nums[1] = 3;
```

Сравниваем:

```text
3 == 5 — false
3 < 5  — true
```

Следовательно, выполняется:

```java
left = mid + 1;
left = 2;
```

Индексы `0` и `1` больше проверять не нужно.

### Шаг 3. Повторяем поиск

Теперь:

```text
left = 2
right = 3
```

Вычисляем середину:

```java
mid = 2 + (3 - 2) / 2;
mid = 2;
```

Получаем:

```java
nums[2] = 5;
```

Проверяем:

```java
nums[mid] == target
5 == 5
```

Условие истинно.

Выполняется:

```java
return 2;
```

**Ответ: `2`.**

Число `5` найдено по индексу `2`.

## 12. Проверка граничных случаев

Хорошее решение должно корректно работать не только на трёх примерах из условия, но и на граничных значениях.

| Массив | `target` | Результат | Объяснение |
|---|---:|---:|---|
| `[1, 3, 5, 6]` | `1` | `0` | Первый элемент найден |
| `[1, 3, 5, 6]` | `6` | `3` | Последний элемент найден |
| `[1, 3, 5, 6]` | `0` | `0` | Вставка в начало |
| `[1, 3, 5, 6]` | `4` | `2` | Вставка между `3` и `5` |
| `[1, 3, 5, 6]` | `7` | `4` | Вставка в конец |
| `[10]` | `5` | `0` | Вставка перед единственным элементом |
| `[10]` | `10` | `0` | Единственный элемент найден |
| `[10]` | `15` | `1` | Вставка после единственного элемента |

### Почему алгоритм работает для всех этих случаев?

- Если цель равна первому элементу, метод возвращает `0`.
- Если цель равна последнему элементу, метод возвращает индекс последнего элемента.
- Если цель меньше всех элементов, границы поиска в итоге приводят к `left = 0`.
- Если цель больше всех элементов, левая граница перемещается на `nums.length`.
- Если массив содержит один элемент, бинарный поиск также корректно обрабатывает его.

Дополнительные проверки для каждого из этих случаев не требуются.

## 13. Доказательство корректности алгоритма

Докажем, что алгоритм возвращает правильный индекс.

### Шаг 1. Изначально рассматривается весь массив

В начале:

```java
left = 0;
right = nums.length - 1;
```

Диапазон включает все элементы массива, поэтому искомый элемент или позиция вставки находятся в рассматриваемом диапазоне либо сразу за его правой границей.

### Шаг 2. На каждом шаге исключается только неподходящая часть

Если:

```java
nums[mid] < target
```

то из-за сортировки все элементы с индексами от `left` до `mid` не могут быть равны `target` и меньше не могут оказаться подходящей позицией для вставки. Поэтому переносим `left` на `mid + 1`.

Если:

```java
nums[mid] > target
```

то все элементы от `mid` до `right` не подходят для поиска целевого значения. Поэтому переносим `right` на `mid - 1`.

Если элемент равен `target`, его индекс немедленно возвращается.

### Шаг 3. Цикл обязательно завершится

На каждом шаге диапазон поиска уменьшается. Количество рассматриваемых элементов конечно, а границы постепенно сближаются.

Поэтому в итоге либо будет найден элемент, либо наступит условие:

```java
left > right
```

### Шаг 4. После завершения `left` указывает на позицию вставки

Если целевое значение не найдено, все элементы слева от `left` меньше `target`, а все элементы справа от `left` больше `target`.

Следовательно, вставка элемента по индексу `left` сохранит сортировку массива.

Таким образом, алгоритм корректно решает задачу.

## 14. Временная и пространственная сложность

### Временная сложность — `O(log n)`

На каждом шаге количество элементов в диапазоне поиска уменьшается примерно в два раза.

Если изначально имеется `n` элементов, то после нескольких итераций останется примерно:

```text
n / 2
n / 4
n / 8
n / 16
...
```

Число таких делений до достижения диапазона размером не более одного элемента пропорционально `log₂(n)`.

Поэтому временная сложность:

```text
O(log n)
```

При максимальной длине массива `10 000` алгоритму требуется порядка 14 делений диапазона, чтобы сузить его до одного элемента; в зависимости от того, считаем ли мы последнее сравнение, число проверок будет отличаться.

### Пространственная сложность — `O(1)`

Алгоритм использует только несколько переменных:

```java
left
right
mid
```

Их количество не зависит от размера массива.

Дополнительные массивы, коллекции и рекурсия не используются.

Следовательно, дополнительная пространственная сложность:

```text
O(1)
```

### Итоговая оценка

| Характеристика | Значение |
|---|---|
| Алгоритм | Бинарный поиск |
| Временная сложность | `O(log n)` |
| Дополнительная память | `O(1)` |
| Изменение исходного массива | Нет |
| Соответствие требованиям задачи | Да |

## 16. Что нужно запомнить

1. **Для отсортированного массива** можно использовать бинарный поиск вместо последовательного перебора.
2. `left` обозначает левую границу диапазона поиска.
3. `right` обозначает правую границу диапазона поиска.
4. `mid` обозначает индекс среднего элемента.
5. Если `nums[mid] == target`, возвращаем `mid`.
6. Если `nums[mid] < target`, выполняем `left = mid + 1`.
7. Если `nums[mid] > target`, выполняем `right = mid - 1`.
8. Если элемент не найден, возвращаем `left`.
9. Временная сложность алгоритма — `O(log n)`.
10. Дополнительная пространственная сложность — `O(1)`.

**Главная мысль:** бинарный поиск позволяет не только находить существующие элементы, но и определять правильную позицию для вставки отсутствующего элемента в отсортированный массив.

Для задачи LeetCode № 35 это оптимальное решение по времени и дополнительной памяти.
