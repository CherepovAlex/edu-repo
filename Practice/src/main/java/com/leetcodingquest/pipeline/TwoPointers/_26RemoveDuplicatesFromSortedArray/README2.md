# LeetCode 26. Удаление дубликатов из отсортированного массива

## 📋 Условие задачи

Дан целочисленный массив `nums`, отсортированный в порядке **неубывания**. Удалите дубликаты **на месте**, чтобы каждый уникальный элемент встречался только один раз. Относительный порядок элементов должен остаться прежним.

Считайте, что количество уникальных элементов в `nums` равно `k`. После удаления дубликатов верните количество уникальных элементов `k`.

Первые `k` элементов `nums` должны содержать уникальные числа в отсортированном порядке. Остальные элементы после индекса `k - 1` можно игнорировать.

### Проверка судьёй

```java
int[] nums = [...];                    // Входной массив
int[] expectedNums = [...];            // Ожидаемый ответ с правильной длиной

int k = removeDuplicates(nums);        // Вызывает вашу реализацию

assert k == expectedNums.length;
for (int i = 0; i < k; i++) {
    assert nums[i] == expectedNums[i];
}
```

Если все утверждения верны, ваше решение будет принято.

### Примеры

**Пример 1:**
```
Входные данные: nums = [1,1,2]
Выходные данные: 2, nums = [1,2,_]
Пояснение: функция должна вернуть k = 2, первые два элемента nums равны 1 и 2.
```

**Пример 2:**
```
Входные данные: nums = [0,0,1,1,1,2,2,3,3,4]
Выходные данные: 5, nums = [0,1,2,3,4,_,_,_,_,_]
Пояснение: функция должна вернуть k = 5.
```

### Ограничения

- `1 <= nums.length <= 3 * 10^4`
- `-100 <= nums[i] <= 100`
- `nums` отсортированы в порядке неубывания

---

## 💡 Ключевая идея

Массив **отсортирован** → все одинаковые элементы идут **подряд**. Значит, для сравнения достаточно смотреть на **последний записанный уникальный элемент** — если текущий отличается от него, это новый уникальный элемент.

Используем **метод двух указателей**:

| Указатель | Роль |
|-----------|------|
| `k` (медленный) | Позиция, куда записывать следующий уникальный элемент. Он же — счётчик уникальных. |
| `i` (быстрый) | Текущий просматриваемый элемент. |

**Сложность:**
- ⏱ Время: **O(n)** — один проход по массиву
- 💾 Память: **O(1)** — дополнительная память не используется
- ✅ In-place: запись идёт в тот же массив, `k` никогда не обгоняет `i`

## 💻 Код решения

```java
public class Solution {

    public int removeDuplicates(int[] nums) {
        // Если массив пустой — уникальных элементов 0 (страховка; по условию длина >= 1)
        if (nums.length == 0) {
            return 0;
        }

        // k — индекс, куда будет записан следующий уникальный элемент.
        // Первый элемент nums[0] уже уникален по определению, поэтому начинаем с 1.
        int k = 1;

        // Проходим по массиву, начиная со второго элемента (индекс 1)
        for (int i = 1; i < nums.length; i++) {
            // Сравниваем текущий элемент с последним записанным уникальным:
            // nums[k - 1] — это последний уникальный элемент в "сжатой" части массива
            if (nums[i] != nums[k - 1]) {
                // Элементы разные — значит nums[i] новый уникальный элемент.
                // Записываем его в позицию k (сразу после последнего уникального)
                nums[k] = nums[i];
                // Увеличиваем счётчик/указатель k — уникальных элементов стало на 1 больше
                k++;
            }
            // Если nums[i] == nums[k - 1], это дубликат — просто пропускаем его
        }

        // Возвращаем количество уникальных элементов.
        // Первые k элементов nums уже содержат уникальные значения в нужном порядке.
        return k;
    }

    public static void main(String[] args) {
        // Создаём объект Solution, чтобы вызвать метод removeDuplicates
        Solution sol = new Solution();

        // ---- Тест 1 ----
        int[] nums1 = {1, 1, 2};                       // входной массив
        int k1 = sol.removeDuplicates(nums1);          // вызываем решение
        System.out.println("k = " + k1);               // печатаем количество уникальных
        System.out.print("nums = [");                  // начинаем печать массива
        for (int i = 0; i < k1; i++) {                 // печатаем только первые k элементов
            System.out.print(nums1[i] + (i < k1 - 1 ? ", " : "")); // через запятую
        }
        System.out.println("]");                       // закрываем скобку

        // ---- Тест 2 ----
        int[] nums2 = {0, 0, 1, 1, 1, 2, 2, 3, 3, 4};
        int k2 = sol.removeDuplicates(nums2);
        System.out.println("k = " + k2);
        System.out.print("nums = [");
        for (int i = 0; i < k2; i++) {
            System.out.print(nums2[i] + (i < k2 - 1 ? ", " : ""));
        }
        System.out.println("]");

        // ---- Тест 3 (свой пример) ----
        int[] nums3 = {1, 2, 2, 3};
        int k3 = sol.removeDuplicates(nums3);
        System.out.println("k = " + k3);
        System.out.print("nums = [");
        for (int i = 0; i < k3; i++) {
            System.out.print(nums3[i] + (i < k3 - 1 ? ", " : ""));
        }
        System.out.println("]");
    }
}
```

**Ожидаемый вывод:**
```
k = 2
nums = [1, 2]
k = 5
nums = [0, 1, 2, 3, 4]
k = 3
nums = [1, 2, 3]
```

## 🔍 Пошаговый разбор Пример 1: `nums = [1, 1, 2]`

Начальное состояние: `nums = [1, 1, 2]`, `k = 1` (первый элемент `nums[0] = 1` уже считается уникальным).

| Шаг | `i` | `nums[i]` | `nums[k-1]` | Сравнение | Действие | Массив после | `k` |
|-----|-----|-----------|-------------|-----------|----------|--------------|-----|
| 1 | 1 | 1 | `nums[0] = 1` | `1 == 1` → дубликат | пропускаем | `[1, 1, 2]` | 1 |
| 2 | 2 | 2 | `nums[0] = 1` | `2 != 1` → новый | `nums[1] = 2`, `k++` | `[1, 2, 2]` | 2 |

Цикл закончился (`i` дошёл до `nums.length = 3`). Возвращаем `k = 2`.
Первые 2 элемента: `[1, 2]` ✅. Остальное (`nums[2] = 2`) игнорируется.

## ✅ Проверка судьёй

### Пример 1
```java
int[] nums = {1, 1, 2};
int[] expectedNums = {1, 2};
int k = removeDuplicates(nums);          // k = 2
assert k == expectedNums.length;         // 2 == 2 ✓
for (int i = 0; i < k; i++) {
    assert nums[i] == expectedNums[i];   // nums[0]=1 ✓, nums[1]=2 ✓
}
```

### Пример 2
```java
int[] nums = {0, 0, 1, 1, 1, 2, 2, 3, 3, 4};
int[] expectedNums = {0, 1, 2, 3, 4};
int k = removeDuplicates(nums);          // k = 5
assert k == expectedNums.length;         // 5 == 5 ✓
for (int i = 0; i < k; i++) {
    assert nums[i] == expectedNums[i];   // nums[0..4] = [0,1,2,3,4] ✓
```

## 🧠 Почему решение оптимально

| Критерий | Оценка | Обоснование |
|----------|--------|-------------|
| **Время** | **O(n)** | Цикл выполняется ровно `n - 1` раз, внутри — одно сравнение и (возможно) одно присваивание. Константные операции → линейное время. |
| **Память** | **O(1)** | Используются только две целочисленные переменные `k` и `i`. Никаких дополнительных массивов и структур. |
| **In-place** | ✅ | Запись идёт в тот же массив `nums`, причём `k` никогда не обгоняет `i` — ещё не просмотренные элементы не затираются. |

---

## 📌 Итог

Метод двух указателей — классический приём для задач с **отсортированными массивами**:

- `k` — «медленный» указатель (граница уникальной части),
- `i` — «быстрый» указатель (перебор всех элементов).

Если текущий элемент отличается от последнего уникального (`nums[k-1]`), мы его сохраняем — так в начале массива формируется сжатая последовательность уникальных значений. Дубликаты автоматически «отбрасываются» в хвост, а `k` в конце равен количеству уникальных элементов.
