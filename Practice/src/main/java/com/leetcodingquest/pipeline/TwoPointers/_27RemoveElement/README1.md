## 1. Условие задачи

**LeetCode № 27 — Remove Element (Удалить элемент).**

Дан целочисленный массив `nums` и целое число `val`.

Необходимо удалить все вхождения значения `val` из массива `nums` и вернуть количество элементов, которые не равны `val`.

Обозначим количество оставшихся элементов через `k`.

Чтобы решение было принято, необходимо:

1. Изменить исходный массив `nums`.
2. Разместить все элементы, не равные `val`, в первых `k` позициях.
3. Вернуть число `k`.
4. Не создавать дополнительный массив для хранения результата.

Порядок элементов может изменяться. Элементы после позиции `k - 1` не имеют значения.

### Ограничения

- `0 <= nums.length <= 100`
- `0 <= nums[i] <= 50`
- `0 <= val <= 100`

### Сигнатура метода

```java
public int removeElement(int[] nums, int val)
```

Метод принимает массив и значение для удаления, изменяет исходный массив и возвращает количество оставшихся элементов.

## 2. Примеры

### Пример 1

**Входные данные:**

```text
nums = [3, 2, 2, 3]
val = 3
```

**Результат:**

```text
k = 2
nums = [2, 2, _, _]
```

Число `3` встречается дважды. После его удаления остаются два элемента со значением `2`.

### Пример 2

**Входные данные:**

```text
nums = [0, 1, 2, 2, 3, 0, 4, 2]
val = 2
```

**Результат:**

```text
k = 5
nums = [0, 1, 3, 0, 4, _, _, _]
```

Все три вхождения числа `2` пропускаются. Остаются пять элементов: `0`, `1`, `3`, `0`, `4`.

Другой допустимый результат:

```text
nums = [0, 1, 4, 0, 3, _, _, _]
```

Порядок элементов не обязан сохраняться.

### Пример 3

**Входные данные:**

```text
nums = []
val = 5
```

**Результат:**

```text
k = 0
nums = []
```

Массив пустой, поэтому удалять нечего. Метод должен вернуть `0`.

## 3. Что нужно понять перед решением

### 3.1. Почему нельзя просто удалить элемент из массива?

В Java размер массива фиксируется при создании.

Например:

```java
int[] nums = {3, 2, 2, 3};
```

Длина этого массива всегда равна `4`. Удалить из него ячейку так, чтобы длина стала `3`, нельзя.

Вместо этого мы перезаписываем начало массива подходящими значениями.

Например, после обработки массива `[3, 2, 2, 3]` можно получить:

```text
Индексы:  0  1  2  3
Массив:  [2, 2, 2, 3]
```

Первые два элемента являются результатом. Остальные значения игнорируются.

Размер массива по-прежнему равен `4`, но метод возвращает `2`.

### 3.2. Что такое индекс?

Индекс — это позиция элемента в массиве.

В Java индексация начинается с нуля.

Для массива:

```java
int[] nums = {3, 2, 2, 3};
```

Получаем:

| Индекс | Значение |
|---:|---:|
| 0 | 3 |
| 1 | 2 |
| 2 | 2 |
| 3 | 3 |

Чтобы получить первый элемент, используем `nums[0]`, а не `nums[1]`.

### 3.3. Что означает переменная `k`?

Переменная `k` выполняет две задачи:

- Хранит количество найденных элементов, которые не равны `val`.
- Показывает индекс, куда нужно записать следующий подходящий элемент.

Например, если мы уже нашли три подходящих элемента, то `k = 3`.

Индексы этих элементов — `0`, `1` и `2`. Следующий подходящий элемент необходимо записать в `nums[3]`.

Поэтому после каждой успешной записи мы увеличиваем `k` на единицу.

## 4. Идея алгоритма

Используем алгоритм двух указателей. В этой задаче оба указателя движутся слева направо, но выполняют разные задачи.

### Указатель `i`

Отвечает за чтение элементов массива.

Он последовательно проверяет каждый элемент от `nums[0]` до `nums[nums.length - 1]`.

### Указатель `k`

Отвечает за запись элементов, которые необходимо сохранить.

Он начинает с нуля и увеличивается только тогда, когда мы находим элемент, не равный `val`.

### Алгоритм по шагам

1. Создаём переменную `k` и устанавливаем её в `0`.
2. Запускаем цикл по всем элементам массива с помощью `i`.
3. Сравниваем текущий элемент `nums[i]` со значением `val`.
4. Если `nums[i] == val`, пропускаем элемент.
5. Если `nums[i] != val`, записываем его в `nums[k]`.
6. Увеличиваем `k` на единицу.
7. После завершения цикла возвращаем `k`.

### Псевдокод

```text
k = 0

для каждого элемента nums[i]:
    если nums[i] не равно val:
        nums[k] = nums[i]
        k = k + 1

вернуть k
```

### Почему не нужно сдвигать элементы вручную?

Можно было бы удалять элементы с помощью сдвига оставшейся части массива, но тогда одна операция удаления могла бы потребовать перемещения нескольких элементов.

Наш алгоритм просто записывает подходящие значения в начало массива. Поэтому достаточно одного прохода.

## 5. Решение на Java

Ниже приведён полный класс `Solution1`, который можно скопировать в IntelliJ IDEA и запустить самостоятельно.

Каждая строка кода снабжена комментарием.

```java
public class Solution1 { // Объявляем класс с решением задачи LeetCode № 27.

    public int removeElement(int[] nums, int val) { // Объявляем метод: nums — исходный массив, val — удаляемое значение.

        int k = 0; // Храним количество подходящих элементов и индекс следующей позиции для записи.

        for (int i = 0; i < nums.length; i++) { // Перебираем каждый элемент массива от индекса 0 до последнего.

            if (nums[i] != val) { // Проверяем, отличается ли текущий элемент от значения, которое нужно удалить.

                nums[k] = nums[i]; // Записываем подходящий элемент в начало массива на позицию k.

                k++; // Увеличиваем количество сохранённых элементов на единицу.
            } // Если элемент равен val, пропускаем его и не увеличиваем k.

        } // Завершаем цикл после обработки всех элементов массива.

        return k; // Возвращаем количество элементов, не равных val.
    } // Завершаем метод removeElement.

    public static void main(String[] args) { // Объявляем точку входа для запуска программы в IntelliJ IDEA.

        Solution1 solution = new Solution1(); // Создаём объект класса для вызова нестатического метода.

        int[] nums1 = {3, 2, 2, 3}; // Создаём массив для первого примера.
        int val1 = 3; // Указываем значение, которое нужно удалить.
        int k1 = solution.removeElement(nums1, val1); // Удаляем логически все вхождения val1 и получаем количество оставшихся элементов.

        System.out.println("Пример 1: k = " + k1); // Выводим количество оставшихся элементов.
        System.out.print("Значимая часть массива: "); // Выводим заголовок перед элементами результата.

        for (int i = 0; i < k1; i++) { // Перебираем только первые k1 элементов, которые являются результатом.
            System.out.print(nums1[i] + " "); // Выводим очередной элемент результата.
        } // Завершаем цикл вывода первого примера.

        System.out.println(); // Переходим на новую строку.

        int[] nums2 = {0, 1, 2, 2, 3, 0, 4, 2}; // Создаём массив для второго примера.
        int val2 = 2; // Указываем число, которое нужно удалить.
        int k2 = solution.removeElement(nums2, val2); // Вызываем метод и получаем количество оставшихся элементов.

        System.out.println("Пример 2: k = " + k2); // Выводим количество оставшихся элементов.
        System.out.print("Значимая часть массива: "); // Выводим заголовок перед элементами результата.

        for (int i = 0; i < k2; i++) { // Перебираем только первые k2 элементов массива.
            System.out.print(nums2[i] + " "); // Выводим очередной элемент результата.
        } // Завершаем цикл вывода второго примера.

        System.out.println(); // Переходим на новую строку.

        int[] nums3 = {}; // Создаём пустой массив для третьего примера.
        int val3 = 5; // Указываем значение, которое нужно удалить.
        int k3 = solution.removeElement(nums3, val3); // Вызываем метод для пустого массива.

        System.out.println("Пример 3: k = " + k3); // Выводим количество оставшихся элементов.
        System.out.print("Значимая часть массива: "); // Выводим заголовок результата.

        for (int i = 0; i < k3; i++) { // Проверяем, есть ли элементы для вывода; при k3 = 0 цикл не выполняется.
            System.out.print(nums3[i] + " "); // Выводим элемент результата, если он существует.
        } // Завершаем цикл вывода третьего примера.

        System.out.println("(пустой массив)"); // Выводим сообщение о пустом результате.
    } // Завершаем метод main.
} // Завершаем класс Solution1.
```

### Ожидаемый результат запуска

```text
Пример 1: k = 2
Значимая часть массива: 2 2
Пример 2: k = 5
Значимая часть массива: 0 1 3 0 4
Пример 3: k = 0
Значимая часть массива: (пустой массив)
```

**Важно:** на LeetCode обычно нужно отправлять только метод `removeElement` внутри класса `Solution`. Метод `main` необходим для самостоятельного запуска и проверки программы.

## 6. Пошаговый разбор примера 1

### Исходные данные

```java
nums = [3, 2, 2, 3]
val = 3
```

Длина массива равна `4`.

В начале метода выполняется:

```java
int k = 0;
```

Это означает, что пока не найдено ни одного элемента, который нужно сохранить.

Рассмотрим все итерации цикла.

### Шаг 1. Индекс `i = 0`

Текущий элемент:

```java
nums[0] = 3
```

Проверяем условие:

```java
if (nums[i] != val)
```

Подставляем значения:

```java
if (3 != 3)
```

Условие ложно, потому что `3` равно `3`.

Поэтому тело `if` не выполняется:

- Элемент не записывается в начало массива.
- `k` не увеличивается.
- Значение `k` остаётся равным `0`.

Массив пока не изменился:

```text
[3, 2, 2, 3]
```

### Шаг 2. Индекс `i = 1`

Текущий элемент:

```java
nums[1] = 2
```

Проверяем условие:

```java
if (2 != 3)
```

Условие истинно.

Выполняется первая операция:

```java
nums[k] = nums[i];
```

Подставляем значения:

```java
nums[0] = nums[1];
```

То есть:

```java
nums[0] = 2;
```

Массив теперь выглядит так:

```text
[2, 2, 2, 3]
```

Затем выполняется:

```java
k++;
```

Значение `k` изменяется с `0` на `1`.

Теперь один элемент сохранён.

### Шаг 3. Индекс `i = 2`

Текущий элемент:

```java
nums[2] = 2
```

Проверяем:

```java
if (2 != 3)
```

Условие истинно.

Записываем элемент на позицию `k`, которая сейчас равна `1`:

```java
nums[1] = nums[2];
```

Получаем:

```text
[2, 2, 2, 3]
```

Затем:

```java
k++;
```

Теперь `k = 2`.

В начале массива находятся два сохранённых элемента.

### Шаг 4. Индекс `i = 3`

Текущий элемент:

```java
nums[3] = 3
```

Проверяем:

```java
if (3 != 3)
```

Условие ложно.

Элемент пропускается. Переменная `k` остаётся равной `2`.

### Завершение цикла

После проверки всех четырёх элементов цикл завершается.

Выполняется:

```java
return k;
```

Метод возвращает `2`.

**Ответ:**

```text
k = 2
nums = [2, 2, _, _]
```

Подчёркивания обозначают позиции, содержимое которых не проверяется.

### Сводная таблица

| `i` | `nums[i]` | Действие | `k` после шага |
|---:|---:|---|---:|
| 0 | 3 | Пропускаем | 0 |
| 1 | 2 | Записываем в `nums[0]` | 1 |
| 2 | 2 | Записываем в `nums[1]` | 2 |
| 3 | 3 | Пропускаем | 2 |

## 8. Пошаговый разбор примера 3

### Исходные данные

```java
nums = []
val = 5
```

Это пустой массив.

При входе в метод выполняется:

```java
int k = 0;
```

Теперь `k` равен `0`.

Далее начинается цикл:

```java
for (int i = 0; i < nums.length; i++)
```

Поскольку длина массива равна нулю, проверка условия выглядит так:

```java
0 < 0
```

Она возвращает `false`.

Поэтому тело цикла не выполняется ни разу.

Программа не обращается к `nums[0]`, следовательно, ошибка выхода за границы массива не возникает.

После завершения цикла выполняется:

```java
return k;
```

Метод возвращает `0`.

**Ответ:**

```text
k = 0
nums = []
```

Этот пример показывает, что алгоритм корректно обрабатывает пустой массив без специальных дополнительных проверок.

## 9. Почему алгоритм работает

Докажем правильность решения.

### 9.1. В начале

Изначально `k = 0`.

Мы ещё не обработали ни одного элемента, поэтому в начале массива нет сохранённых элементов. Это соответствует условию алгоритма.

### 9.2. Во время обработки

На каждой итерации рассматриваем очередной элемент `nums[i]`.

Возможны два случая.

**Случай 1. `nums[i] == val`.**

Этот элемент не нужно сохранять. Поэтому мы ничего не записываем и не увеличиваем `k`.

Количество сохранённых элементов остаётся правильным.

**Случай 2. `nums[i] != val`.**

Этот элемент необходимо сохранить.

Мы записываем его в `nums[k]`, после чего увеличиваем `k`.

Таким образом, все найденные подходящие элементы располагаются подряд в начале массива.

Поскольку `k` увеличивается только при сохранении элемента, оно всегда равно количеству подходящих элементов, обработанных к текущему моменту.

### 9.3. После завершения цикла

Цикл проверил все элементы массива.

Следовательно, в первые `k` позиций записаны все элементы исходного массива, которые не равны `val`.

Значение `k` равно их количеству.

Поэтому возврат `k` является правильным ответом.

---

## 10. Оценка сложности

Обозначим длину массива через `n`.

### Временная сложность: O(n)

Цикл проходит по каждому элементу массива один раз.

Для каждого элемента выполняется сравнение и, если необходимо, запись и увеличение счётчика.

Количество операций растёт линейно с длиной массива.

Итоговая временная сложность:

**O(n)**

### Дополнительная пространственная сложность: O(1)

Алгоритм использует только несколько переменных:

- `i` — индекс чтения;
- `k` — количество сохранённых элементов;
- `val` — входное значение.

Дополнительный массив не создаётся.

Итоговая дополнительная пространственная сложность:

**O(1)**

### Итоговая оценка

| Показатель | Значение |
|---|---|
| Временная сложность | O(n) |
| Дополнительная память | O(1) |
| Проходы по массиву | 1 |
| Создание нового массива | Нет |
| Изменение исходного массива | Да |

Алгоритм оптимален по асимптотической временной сложности: в общем случае каждый элемент необходимо проверить хотя бы один раз.

## 11. Типичные ошибки

### Ошибка 1. Увеличивать `k` на каждой итерации

Неправильный вариант:

```java
for (int i = 0; i < nums.length; i++) { // Перебираем весь массив.
    if (nums[i] != val) { // Проверяем, нужно ли сохранить элемент.
        nums[k] = nums[i]; // Записываем подходящий элемент.
    } // Завершаем условие.
    k++; // Ошибка: счётчик увеличивается даже при удалении элемента.
} // Завершаем цикл.
```

Почему это неправильно?

Если текущий элемент равен `val`, его нужно пропустить. Но в этом коде `k` всё равно увеличивается.

В результате `k` перестаёт отражать количество сохранённых элементов.

**Правило:** увеличивать `k` нужно только тогда, когда найден элемент, который необходимо оставить.

### Ошибка 2. Возвращать `nums.length`

Неправильно:

```java
return nums.length; // Возвращаем исходную длину массива.
```

Размер массива в Java не меняется.

Если исходный массив содержит восемь элементов, `nums.length` по-прежнему равен `8`, даже если после обработки осталось пять значимых элементов.

Правильно:

```java
return k; // Возвращаем количество элементов, не равных val.
```

### Ошибка 3. Создавать новый массив

Например:

```java
int[] result = new int[nums.length]; // Создаём дополнительный массив.
```

Для этой задачи дополнительный массив не нужен. Условие требует изменить исходный массив, а решение должно использовать постоянное количество дополнительной памяти.

Поэтому записываем элементы непосредственно в `nums`.

### Ошибка 4. Считать, что после `k` обязательно должны находиться подчёркивания

Подчёркивания в примерах обозначают не реальные значения массива, а то, что оставшиеся позиции не проверяются.

Например, допустимый результат:

```text
nums = [2, 2, 2, 3]
k = 2
```

Хотя в массиве всё ещё есть `3`, решение правильное, потому что первые два элемента равны `2`.

### Ошибка 5. Считать, что порядок элементов обязан сохраняться

Условие разрешает изменять порядок элементов.

Для второго примера оба результата допустимы:

```text
[0, 1, 3, 0, 4]
[0, 1, 4, 0, 3]
```

В обоих случаях первые пять элементов содержат все значения, не равные `2`, с правильным количеством повторений.

## 12. Итог

Для решения LeetCode № 27 используется алгоритм двух указателей.

Основная идея — просмотреть массив один раз и записать в его начало только те элементы, которые не равны `val`.

Главные правила:

1. `i` последовательно читает элементы массива.
2. `k` указывает, куда записывать следующий подходящий элемент.
3. Если `nums[i] == val`, пропускаем элемент.
4. Если `nums[i] != val`, выполняем `nums[k] = nums[i]` и увеличиваем `k`.
5. После завершения цикла возвращаем `k`.
6. Значимыми являются только первые `k` элементов массива.

**Сложность решения:**

- Время — O(n).
- Дополнительная память — O(1).

Это простое, эффективное решение, которое использует исходный массив и не требует дополнительных коллекций.
