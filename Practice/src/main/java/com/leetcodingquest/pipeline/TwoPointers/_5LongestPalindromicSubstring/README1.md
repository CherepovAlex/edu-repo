Задача 5. Самая длинная палиндромная подстрока — Java
Разберём задачу как на занятии по Java-разработке: сначала поймём условие, затем рассмотрим алгоритм, докажем его корректность, напишем код с комментарием к каждой строке и пошагово выполним вычисления на примерах.

Выберем оптимальный по времени и достаточно эффективный по памяти алгоритм — расширение от центра (Expand Around Center).

Его сложность:
- Время: \(O(n^2)\) в худшем случае.
- Дополнительная память: \(O(1)\), если не учитывать строку результата.
При ограничении \(n \leq 1000\) это отличное решение.
1. Что требуется сделать?
Дана строка s. Нужно вернуть её самую длинную палиндромную подстроку.

Палиндром — это последовательность символов, которая читается одинаково слева направо и справа налево.

Например:
- "abba" — палиндром.
- "aba" — палиндром.
- "1221" — палиндром.
- "abc" — не палиндром.
- "babad" — содержит палиндромные подстроки "bab" и "aba".
Важно различать два понятия:
- Подстрока — символы, расположенные подряд в исходной строке.
- Подпоследовательность — символы, которые могут находиться не подряд.
Нам нужна именно подстрока. Например, в строке "abc" нельзя вернуть "ac", потому что эти символы не стоят рядом.
2. Идея решения
Главное свойство палиндрома: его левая и правая части зеркально совпадают относительно центра.

Рассмотрим строку:
Нечётный палиндром — центр в одном символе
b

0

a

1

b

2

a

3

d

4


Если взять центр в индексе 1 (символ a), сравниваем a с a, затем b с b. Получаем "bab".

Чётный палиндром — центр между двумя символами
c

0

b

1

b

2

d

3


В строке "cbbd" два символа b одинаковы, поэтому расширение от центра между индексами 1 и 2 даёт "bb".

Таким образом, возможны два типа центра:
1. Нечётный палиндром: один центральный символ. Например, "racecar" или "aba".
2. Чётный палиндром: центр между двумя символами. Например, "abba" или "bb".
Почему необходимо проверять оба типа? Потому что если искать только от одного центрального символа, можно пропустить "bb", "abba" и другие палиндромы чётной длины.
3. Как работает алгоритм
Будем последовательно перебирать каждый возможный центр строки.

Для каждого индекса i выполняем две проверки:
1. Расширяемся от центра (i, i) — ищем нечётный палиндром.
2. Расширяемся от центра (i, i + 1) — ищем чётный палиндром.
При расширении сравниваем два символа:
- левый: s.charAt(left);
- правый: s.charAt(right).
Если они одинаковы, значит, текущий отрезок остаётся палиндромом. Сдвигаем левую границу на один символ влево, а правую — на один вправо.

Если символы отличаются или мы вышли за границы строки, расширение останавливается.

Затем вычисляем длину найденного палиндрома и сохраняем его границы, если он длиннее лучшего результата, найденного ранее.
4. Полный код на Java с комментариями к каждой строке
В LeetCode нужно реализовать метод longestPalindrome внутри класса Solution. Вспомогательный метод expandAroundCenter можно добавить в тот же класс.

class Solution {

    public String longestPalindrome(String s) {
        int start = 0;       // Начальный индекс самого длинного палиндрома.
        int maxLength = 1;   // Длина самого длинного палиндрома, найденного на данный момент.

        for (int i = 0; i < s.length(); i++) { // Перебираем каждый индекс как возможный центр.

            int len1 = expandAroundCenter(s, i, i);     // Ищем нечётный палиндром с центром в i.
            int len2 = expandAroundCenter(s, i, i + 1); // Ищем чётный палиндром между i и i + 1.

            int len = Math.max(len1, len2); // Выбираем более длинный из двух найденных палиндромов.

            if (len > maxLength) { // Обновляем результат, только если нашли палиндром длиннее.
                maxLength = len;   // Запоминаем новую максимальную длину.
                start = i - (len - 1) / 2; // Вычисляем начальный индекс палиндрома.
            }
        }

        return s.substring(start, start + maxLength); // Возвращаем найденную подстроку.
    }

    private int expandAroundCenter(String s, int left, int right) {
        // Расширяем границы, пока они внутри строки и символы совпадают.
        while (left >= 0
                && right < s.length()
                && s.charAt(left) == s.charAt(right)) {

            left--;  // Сдвигаем левую границу на один символ влево.
            right++; // Сдвигаем правую границу на один символ вправо.
        }

        return right - left - 1; // Возвращаем длину последнего корректного палиндрома.
    }
}



Теперь разберём, почему каждая часть работает именно так.
5. Подробный разбор кода
5.1. Инициализация переменных
int start = 0;
int maxLength = 1;


start — индекс, с которого начинается лучший найденный палиндром.

maxLength — длина этого палиндрома.

Почему изначально maxLength = 1? По условию длина строки не меньше 1. Любой одиночный символ является палиндромом, поэтому мы уже гарантированно знаем ответ длиной хотя бы 1.

Например, для строки "abc" любой символ, взятый отдельно, является палиндромом. Если более длинного палиндрома нет, ответом будет один символ.
5.2. Перебор центров
for (int i = 0; i < s.length(); i++)


Переменная i последовательно принимает значения от 0 до s.length() - 1.

Для строки "babad" индексы выглядят так:
Индекс	0	1	2	3	4
Символ	b	a	b	a	d
Каждый индекс рассматривается как центр нечётного палиндрома. Одновременно проверяется центр между текущим индексом и следующим.
5.3. Проверка двух типов центров
int len1 = expandAroundCenter(s, i, i);
int len2 = expandAroundCenter(s, i, i + 1);


Первая строка передаёт одинаковые границы left = i и right = i. Это центр внутри символа.

Вторая строка передаёт left = i и right = i + 1. Это центр между соседними символами.

Например, в "aba" вызов с (1, 1) находит "aba", а вызов с (1, 2) не находит палиндрома длиной больше нуля.

В строке "bb" вызов с (0, 1) находит "bb", тогда как нечётная проверка находит лишь одиночные символы.
5.4. Как работает расширение
while (left >= 0
        && right < s.length()
        && s.charAt(left) == s.charAt(right))


Цикл продолжает работу, пока одновременно выполняются три условия:
1. left >= 0 — левая граница не вышла за начало строки.
2. right < s.length() — правая граница не вышла за конец строки.
3. s.charAt(left) == s.charAt(right) — символы на обеих границах одинаковы.
Если хотя бы одно условие перестаёт выполняться, цикл завершается.

Внутри цикла:
left--;
right++;


Мы расширяем проверяемый отрезок на один символ с каждой стороны.

Допустим, проверяем "cbbd" с центром между двумя b:
- Сначала сравниваем b и b — совпадают.
- Затем сравниваем c и d — не совпадают.
- Останавливаемся. Самый длинный палиндром вокруг этого центра — "bb".
5.5. Почему возвращается right - left - 1?
return right - left - 1;


Это важная деталь алгоритма.

Когда цикл завершается, границы уже сдвинуты на один шаг дальше последнего подходящего палиндрома.

Например, для "bb":
- Сначала left = 0, right = 1.
- Символы совпадают.
- Границы сдвигаются: left = -1, right = 2.
- Цикл заканчивается, потому что left < 0.
Получаем:
\[
2 - (-1) - 1 = 2
\]

Длина палиндрома равна 2.

Вычитание единицы компенсирует то, что обе границы уже вышли за пределы палиндрома.
5.6. Обновление лучшего результата
int len = Math.max(len1, len2);

if (len > maxLength) {
    maxLength = len;
    start = i - (len - 1) / 2;
}


Из двух вариантов выбираем самый длинный.

Если он длиннее предыдущего лучшего результата, обновляем длину и начальный индекс.

Формула начала:
\[
start = i - \left\lfloor\frac{len-1}{2}\right\rfloor
\]

Она подходит для обоих типов палиндрома:
- Для нечётной длины центр находится на символе i.
- Для чётной длины центр находится между i и i + 1.
Например, при i = 1 и len = 4 начало равно 1 - 1 = 0. Это соответствует палиндрому "abba" с индексами от 0 до 3.
5.7. Возврат результата
return s.substring(start, start + maxLength);


Метод substring(beginIndex, endIndex) возвращает подстроку от beginIndex включительно до endIndex не включительно.

Например:
"babad".substring(0, 3)


возвращает "bab".

Именно поэтому второй аргумент равен start + maxLength, а не последнему индексу символа.

6. Пошаговое выполнение примера 1
Входные данные:
s = "babad"


Ожидаемый ответ — "bab". Также правильным ответом является "aba".
Шаг 1. Начальное состояние
start = 0
maxLength = 1


Исходная строка:
b

0

a

1

b

2

a

3

d

4


Лучший найденный палиндром пока состоит из одного символа: "b".

Шаг 2. Итерация i = 0
Центр — первый символ b.
- Нечётный центр (0, 0): символ b совпадает сам с собой. Расширяемся, но левая граница выходит за строку.
- Длина нечётного палиндрома: len1 = 1.
- Чётный центр (0, 1): сравниваем b и a. Они различаются, поэтому len2 = 0.
Получаем:
len = max(1, 0) = 1


Поскольку len не больше maxLength, состояние не меняется.
Шаг 3. Итерация i = 1
Центр — символ a.

Нечётная проверка (1, 1):
1. Сравниваем a и a — совпадают.
2. Расширяемся: left = 0, right = 2.
3. Сравниваем b и b — совпадают.
4. Расширяемся: left = -1, right = 3.
5. Левая граница вышла за строку — останавливаемся.
Найден палиндром "bab" длиной 3.

Чётная проверка (1, 2) сравнивает a и b: символы различаются, поэтому длина равна 0.

Теперь:
len = max(3, 0) = 3
3 > 1


Обновляем результат:
maxLength = 3
start = 1 - (3 - 1) / 2 = 0


Лучший палиндром теперь "bab".
Шаг 4. Итерация i = 2
Центр — второй b.

Нечётная проверка находит "aba":
1. Сравниваем b с b.
2. Расширяемся: left = 1, right = 3.
3. Сравниваем a с a.
4. Расширяемся: left = 0, right = 4.
5. Сравниваем b с d — символы различаются.
Длина "aba" равна 3. Чётная проверка (2, 3) сразу останавливается: b не равно a.

Получаем:
len = 3
maxLength = 3


Условие len > maxLength ложно: 3 > 3 — неверно. Поэтому ранее найденный "bab" сохраняется.
Шаг 5. Итерации i = 3 и i = 4
Новые палиндромы длиной больше 3 не находятся. Значения start = 0 и maxLength = 3 остаются прежними.
Итог примера 1
return s.substring(0, 3);


Результат:
"bab"


Обрати внимание: алгоритм не обязан возвращать "aba", даже если эта подстрока тоже максимальной длины. Мы обновляем результат только при строгом условии len > maxLength, поэтому сохраняется первый найденный максимальный палиндром.

Входные данные:
s = "cbbd"


Ожидаемый ответ — "bb".

start = 0

Индексы строки:

Шаг 2. Итерация i = 0
- Нечётный центр (0, 0) находит "c" длиной 1.
- Чётный центр (0, 1) сравнивает c и b. Они различаются.
Длина лучшего кандидата равна 1. Обновления нет.
Шаг 3. Итерация i = 1
Здесь находится ключевой момент.

Нечётный центр (1, 1):
- Символ b совпадает с самим собой.
- Расширение останавливается на границе c и b, которые не совпадают.
Длина нечётного палиндрома равна 1.

Чётный центр (1, 2):
c

0

b

1

b

2

d

3


Первое сравнение: b == b. Символы совпадают, значит, найден палиндром "bb".

Далее алгоритм расширяет границы:
1. Сначала left = 1, right = 2: b == b.
2. Затем left = 0, right = 3: сравниваются c и d.
3. c != d, поэтому расширение прекращается.
Вычисляем длину:
len2 = 3 - 0 - 1 = 2


Выбираем лучший вариант:
len = max(1, 2) = 2


Поскольку 2 > 1, обновляем переменные:
maxLength = 2
start = 1 - (2 - 1) / 2 = 1


Шаг 4. Итерации i = 2 и i = 3
- При i = 2 обнаруживаются только палиндромы длиной 1 или 0.
- При i = 3 находится одиночный символ d.
Палиндром длиннее "bb" не обнаруживается.
Итог примера 2
return s.substring(1, 3);


Результат:
"bb"



8. Третий дополнительный пример: "abba"
В условии указаны два примера, поэтому добавим третий, чтобы отдельно проверить чётный палиндром длины 4.

Входные данные:
s = "abba"


Изначально:
start = 0
maxLength = 1


Рассмотрим итерацию i = 1, где находится первый символ b.

Нечётная проверка (1, 1):
1. b == b — совпадение.
2. Расширяемся до индексов 0 и 2.
3. Сравниваем a и b — несовпадение.
4. Длина нечётного палиндрома равна 1.
Чётная проверка (1, 2):
a

0

b

1

b

2

a

3


Сначала сравниваем b и b, затем a и a. Все четыре символа образуют палиндром "abba".

Расширение проходит так:
Шаг	left	right	Сравнение	Результат
1	1	2	b == b	Расширяемся
2	0	3	a == a	Расширяемся
3	-1	4	Выход за границы	Стоп
Длина найденного палиндрома:
\[
len = 4 - (-1) - 1 = 4
\]

Обновляем результат:
maxLength = 4
start = 1 - (4 - 1) / 2 = 0


В итоге возвращаем:
return s.substring(0, 4);


Результат — "abba".
9. Сложность алгоритма
Обозначим длину строки через \(n\).
Характеристика	Сложность	Объяснение
Время	\(O(n^2)\)	Перебираем до \(n\) центров, а из каждого можем расширяться до \(O(n)\) символов
Дополнительная память	\(O(1)\)	Используем только несколько целочисленных переменных
Возвращаемая строка	\(O(n)\)	Для хранения результата может потребоваться до \(n\) символов
Важное уточнение об оптимальности: решение с расширением от центра оптимально по дополнительной памяти среди этих двух подходов и обычно отлично подходит для LeetCode при ограничении в 1000 символов. Однако оно не оптимально по асимптотическому времени.

Если требуется минимально возможная асимптотическая сложность по времени, существует алгоритм Манакера (Manacher's Algorithm): он решает задачу за \(O(n)\) времени и \(O(n)\) дополнительной памяти. Это более сложный алгоритм, зато он линейный по времени.

Для обучения я рекомендую сначала освоить расширение от центра: оно проще, нагляднее и хорошо объясняет структуру палиндромов.
10. Что важно запомнить перед собеседованием
1. Палиндромы бывают чётной и нечётной длины — проверять нужно оба варианта центра.
2. При расширении сравниваем символы слева и справа, пока они совпадают и границы не выходят за строку.
3. right - left - 1 возвращает длину, потому что границы после цикла уже вышли за последний подходящий символ.
4. substring(start, start + maxLength) использует конечный индекс, который не включается в результат.
5. Если обновлять ответ только при len > maxLength, алгоритм сохраняет первый из найденных палиндромов максимальной длины.
Главная идея задачи: вместо проверки всех возможных подстрок мы используем свойство симметрии палиндрома и расширяемся от каждого возможного центра. Это позволяет решить задачу за \(O(n^2)\) времени и \(O(1)\) дополнительной памяти.
