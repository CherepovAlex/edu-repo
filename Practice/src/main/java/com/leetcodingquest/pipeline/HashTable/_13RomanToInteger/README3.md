# LeetCode 13: Roman to Integer

**Уровень сложности:** Easy  
**Теги:** `String`, `Math`, `Hash Table`

## 📖 Описание задачи

Римские цифры обозначаются семью различными символами: `I`, `V`, `X`, `L`, `C`, `D` и `M`.

| Символ | Значение |
| :--- | :--- |
| I | 1 |
| V | 5 |
| X | 10 |
| L | 50 |
| C | 100 |
| D | 500 |
| M | 1000 |

Например, 2 записывается как `II` (просто две единицы). 12 записывается как `XII` (X + II). 27 записывается как `XXVII` (XX + V + II).

Обычно римские цифры пишутся от большего к меньшему слева направо. Однако число 4 записывается не как `IIII`, а как `IV` (1 перед 5, вычитание). То же самое для 9 (`IX`).

**Задача:** Преобразовать строку, содержащую римскую цифру, в целое число.

**Ограничения:**
*   $1 \le s.length \le 15$
*   $s$ содержит только символы `('I', 'V', 'X', 'L', 'C', 'D', 'M')`.
*   Гарантируется, что $s$ является допустимой римской цифрой в диапазоне $[1, 3999]$.

---

## 💡 Подход к решению

Самое важное правило для преобразования:
1.  **Сложение:** Если символ имеет значение больше или равное следующему за ним, мы добавляем его значение.
2.  **Вычитание:** Если символ имеет значение меньше следующего за ним, мы вычитаем его значение (так как он является "корректирующим" для следующего большого символа).

### Оптимальная стратегия: Проход справа налево

Вместо того чтобы смотреть вперед (текущий символ vs следующий), проще идти **с конца строки к началу**.

1.  Мы начинаем с последнего символа. Его значение всегда добавляется к результату.
2.  На каждом шаге мы сравниваем текущее значение с значением предыдущего (которое было справа от текущего).
3.  Если `currentValue < previousValue`, это значит, что текущий символ стоит перед большим и должен быть вычтен (например, `I` в `IV`).
4.  Если `currentValue >= previousValue`, мы просто добавляем его.

Этот подход позволяет избежать проверки границ массива при доступе к следующему элементу и делает логику очень компактной.

## 🚀 Решение на Java

```java
class Solution {
    /**
     * Преобразует римскую цифру в целое число.
     * 
     * @param s Строка, представляющая римскую цифру
     * @return Целое число, соответствующее римской цифре
     */
    public int romanToInt(String s) {
        // Инициализируем переменную для хранения итогового результата.
        // Начинаем с 0, так как будем накапливать сумму.
        int result = 0;

        // Получаем длину строки для управления циклом.
        int length = s.length();

        // Переменная для хранения значения символа, который был рассмотрен на предыдущем шаге (справа).
        // Изначально 0, так как справа от последнего символа ничего нет.
        int previousValue = 0;

        // Цикл проходит по строке с конца (length - 1) к началу (0).
        // Это позволяет легко сравнивать текущий символ с тем, что был справа от него.
        for (int i = length - 1; i >= 0; i--) {
            
            // Получаем числовое значение текущего римского символа.
            // Например, 'M' -> 1000, 'IV' -> 1 (для символа 'I').
            int currentValue = getRomanValue(s.charAt(i));

            // Проверяем условие вычитания:
            // Если текущее значение МЕНЬШЕ предыдущего (справа), 
            // значит, это случай вычитания (например, I перед V в IV).
            // Мы вычитаем текущее значение из результата.
            if (currentValue < previousValue) {
                result -= currentValue;
            } 
            // Иначе (если текущее значение больше или равно предыдущему),
            // мы просто добавляем текущее значение к результату.
            else {
                result += currentValue;
            }

            // Обновляем previousValue для следующей итерации.
            // Теперь текущий символ станет "предыдущим" для символа слева от него.
            previousValue = currentValue;
        }

        // Возвращаем вычисленное итоговое целое число.
        return result;
    }

    /**
     * Вспомогательный метод для получения числового значения римского символа.
     * Использует switch-case для высокой производительности.
     * 
     * @param c Римский символ
     * @return Числовое значение символа
     */
    private int getRomanValue(char c) {
        switch (c) {
            case 'I': return 1;
            case 'V': return 5;
            case 'X': return 10;
            case 'L': return 50;
            case 'C': return 100;
            case 'D': return 500;
            case 'M': return 1000;
            // По условию задачи входные данные всегда корректны,
            // но default возвращает 0 на случай ошибок или неизвестных символов.
            default: return 0; 
        }
    }
}
```

| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 2 | 'I' | 1 | 0 | `1 < 0` (False) | `result += 1` | 1 |

| 3 | 0 | 'I' | 1 | 1 | `1 < 1` (False) | `result += 1` | 3 |

| 5 | 0 | 'L' | 50 | 5 | `50 < 5` (F) | `+= 50` | 58 |

*Индексы: 0 1 2 3 4 5 6*

| Итерация | Индекс `i` | Символ | `currentValue` | `previousValue` | Сравнение | Действие | `result` | Пояснение |

| 7 | 0 | 'M' | 1000 | 100 | `1000 < 100` (F) | `+= 1000` | 1994 | M добавляется |

**Итог:** 1994

## 📊 Анализ сложности

### Временная сложность: $O(N)$
*   Где $N$ — длина строки `s`.
*   Мы выполняем один проход по строке (цикл `for` от конца до начала).
*   Внутри цикла операции (получение значения символа, сравнение, арифметика) занимают константное время $O(1)$.
*   Общая сложность линейна: $O(N)$.

### Пространственная сложность: $O(1)$
*   Мы используем фиксированное количество переменных: `result`, `length`, `previousValue`, `currentValue`, `i`.
*   Не используется дополнительная память, зависящая от размера входа (нет массивов, HashMap или рекурсии).
*   Память, потребляемая алгоритмом, постоянна.

---

## ✅ Почему это решение эффективно?

1.  **Отсутствие `HashMap`:** Использование `switch-case` быстрее, чем `HashMap`, так как не требует хеширования и обработки коллизий. Для небольшого фиксированного набора ключей (7 символов) `switch` оптимизирован компилятором Java.
2.  **Простота логики:** Алгоритм справа налево избавляет от необходимости проверять наличие следующего символа (`i + 1 < length`), что упрощает код и снижает вероятность ошибок границ массива.
3.  **Читаемость:** Код легко понять и отладить благодаря пошаговой логике сравнения текущего и предыдущего значений.
