# 3644. Максимальное значение K для сортировки перестановки

## 📋 Условие задачи

Дан целочисленный массив `nums` длиной `n`, где `nums` — перестановка чисел в диапазоне `[0..n - 1]`.

Вы можете поменять местами элементы с индексами `i` и `j` только если `nums[i] AND nums[j] == k`, где `AND` обозначает побитовую операцию И, а `k` — неотрицательное целое число.

Верните **максимальное значение `k`** такое, что массив можно отсортировать в неубывающем порядке, используя любое количество таких перестановок. Если `nums` уже отсортирован, верните `0`.

### Примеры

**Пример 1:**
```
Вход:  nums = [0, 3, 2, 1]
Выход: 1
```
Выбираем `k = 1`. Меняем `nums[1] = 3` и `nums[3] = 1`, так как `3 AND 1 == 1`. Получаем `[0, 1, 2, 3]`.

**Пример 2:**
```
Вход:  nums = [0, 1, 3, 2]
Выход: 2
```
Выбираем `k = 2`. Меняем `nums[2] = 3` и `nums[3] = 2`, так как `3 AND 2 == 2`. Получаем `[0, 1, 2, 3]`.

**Пример 3:**
```
Вход:  nums = [3, 2, 1, 0]
Выход: 0
```
Только `k = 0` позволяет выполнить сортировку.

### Ограничения

- `1 <= n == nums.length <= 10^5`
- `0 <= nums[i] <= n - 1`
- `nums` — перестановка целых чисел от `0` до `n - 1`

---

## 💡 Идея решения

Ключевое наблюдение: все «смещённые» элементы (те, для которых `nums[i] != i`) должны быть перемещены на свои правильные позиции. Поскольку каждая перестановка требует `nums[i] AND nums[j] == k`, а `k` одно и то же для всех обменов, то `k` должен быть **общим двоичным подмножеством** всех участвующих в обменах чисел.

Иными словами, `k` должен удовлетворять условию: для каждого смещённого элемента `x` каждый единичный бит `k` должен быть также единичным в `x`. Побитовое И всех смещённых элементов — это в точности множество их «общих единичных битов», то есть **максимально возможное `k`**.

Если массив уже отсортирован, смещённых элементов нет — возвращаем `0`.

### Сложность

| Параметр | Значение |
|----------|----------|
| Время | **O(n)** |
| Память | **O(1)** |

---

## 💻 Код решения (Java)

```java
class Solution {
    public int sortPermutation(int[] nums) {
        int ans = -1;                          // Инициализируем -1 (все биты 1) — нейтральное значение для побитового И
        for (int i = 0; i < nums.length; i++) { // Проходим по каждому индексу i
            if (nums[i] != i) {                // Если текущий элемент стоит не на своей позиции после сортировки
                ans &= nums[i];                // Побитово И с этим смещённым элементом, сужая общие биты
            }
        }
        return ans == -1 ? 0 : ans;            // Если ans остался -1 — массив отсортирован, возвращаем 0
    }
}
```

## 🔍 Пошаговый разбор примеров

### Пример 1: `nums = [0, 3, 2, 1]`

Отсортированный массив должен быть `[0, 1, 2, 3]`.

| Индекс `i` | `nums[i]` | Смещён? | Действие |
|:---:|:---:|:---:|:---|
| 0 | 0 | Нет | Пропускаем |
| 1 | 3 | Да (3 ≠ 1) | `ans = -1 & 3` = **3** (`...111` & `011` = `011`) |
| 2 | 2 | Нет | Пропускаем |
| 3 | 1 | Да (1 ≠ 3) | `ans = 3 & 1` = **1** (`011` & `001` = `001`) |

**Результат:** `ans = 1` → возвращаем **1**.

Проверка: меняем местами `3` и `1`, `3 AND 1 = 1`, сортировка достигается. ✅

---

### Пример 2: `nums = [0, 1, 3, 2]`

Отсортированный массив должен быть `[0, 1, 2, 3]`.

| Индекс `i` | `nums[i]` | Смещён? | Действие |
|:---:|:---:|:---:|:---|
| 0 | 0 | Нет | Пропускаем |
| 1 | 1 | Нет | Пропускаем |
| 2 | 3 | Да (3 ≠ 2) | `ans = -1 & 3` = **3** (`011`) |
| 3 | 2 | Да (2 ≠ 3) | `ans = 3 & 2` = **2** (`011` & `010` = `010`) |

**Результат:** `ans = 2` → возвращаем **2**.

Проверка: меняем местами `3` и `2`, `3 AND 2 = 2`, сортировка достигается. ✅

---

### Пример 3: `nums = [3, 2, 1, 0]`

Отсортированный массив должен быть `[0, 1, 2, 3]`.

| Индекс `i` | `nums[i]` | Смещён? | Действие |
|:---:|:---:|:---:|:---|
| 0 | 3 | Да (3 ≠ 0) | `ans = -1 & 3` = **3** (`011`) |
| 1 | 2 | Да (2 ≠ 1) | `ans = 3 & 2` = **2** (`011` & `010` = `010`) |
| 2 | 1 | Да (1 ≠ 2) | `ans = 2 & 1` = **0** (`010` & `001` = `000`) |
| 3 | 0 | Да (0 ≠ 3) | `ans = 0 & 0` = **0** |

**Результат:** `ans = 0` → возвращаем **0**.

Проверка: у всех смещённых элементов нет общих единичных битов, поэтому только `k = 0` позволяет выполнить обмены. ✅

---

## ✅ Почему решение корректно

Для любого набора элементов, которые нужно поменять местами, `k` должен быть двоичным подмножеством каждого из этих чисел (то есть в каждом числе все биты, где у `k` стоит 1, тоже должны быть 1). Иначе результат побитового И при каком-то обмене окажется меньше `k`, и условие `== k` не выполнится.

Побитовое И всех смещённых элементов даёт в точности все их общие единичные биты — а значит, это и есть максимально возможное `k`.

### Частый вопрос

> Нужно ли учитывать «уже стоящие на месте» элементы как промежуточные для обмена?

Даже если такие элементы участвуют в цепочке обменов, они либо сами входят в цикл смещённых элементов, либо обмен можно выполнить при `k = 0`. Когда `k > 0` допустимо, все необходимые обмены можно выполнить, не нарушая ограничения на общие биты. Поэтому учитывать только смещённые элементы достаточно.

```java
class Solution {
    public int sortPermutation(int[] nums) {
        int ans = -1;
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] != i) {
                ans &= nums[i];
            }
        }
        return ans == -1 ? 0 : ans;
    }
}
```
