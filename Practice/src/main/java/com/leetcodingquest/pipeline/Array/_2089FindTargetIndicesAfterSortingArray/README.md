LeetCode 2089 — Найти целевые индексы после сортировки массива
Разберём задачу как на занятии по Java-разработке: от понимания условия до оптимального алгоритма, кода с комментарием к каждой строке, пошагового вычисления всех трёх примеров и анализа сложности.
1. Понимаем условие задачи
Нам дан массив целых чисел nums и число target.

Нужно представить, что мы сначала сортируем массив по возрастанию, а затем находим все индексы, на которых находится число target.

Важно: индексы начинаются с нуля.

Например, исходный массив:
Исходный массив
1
индекс 0

2
индекс 1

5
индекс 2

2
индекс 3

3
индекс 4


Сортировка по возрастанию

Отсортированный массив
1
индекс 0

2
индекс 1

2
индекс 2

3
индекс 3

5
индекс 4


Если target = 2, ответ — [1, 2], потому что число 2 находится на индексах 1 и 2.

Что нужно учитывать
- Сортировка выполняется по возрастанию.
- В массиве могут быть повторяющиеся числа.
- Нужно вернуть все индексы, на которых находится target.
- Индексы в ответе должны идти по возрастанию.
- Если целевого числа нет, возвращаем пустой список [].
2. Какой алгоритм выбрать?
Есть два основных подхода.

Подход 1. Отсортировать массив и пройти по нему.
1. Сортируем массив.
2. Перебираем его слева направо.
3. Если встречаем target, добавляем индекс в ответ.
Временная сложность — \(O(n\log n)\) из-за сортировки, а дополнительная память зависит от реализации сортировки и размера результирующего списка.

Подход 2. Не сортировать массив, а посчитать числа.

Наблюдение, которое позволяет решить задачу эффективнее:
- Все числа, меньшие target, будут находиться перед ним.
- Все числа, равные target, будут занимать последовательный диапазон индексов.
- Все числа, большие target, будут находиться после него.
Поэтому нам не обязательно сортировать массив. Достаточно посчитать количество чисел, меньших target, и количество чисел, равных target.

Обозначим:
- smaller — количество элементов, которые меньше target.
- equal — количество элементов, которые равны target.
Тогда первый индекс целевого числа равен smaller, а все целевые индексы — это последовательность:
\[
smaller,\ smaller+1,\ \ldots,\ smaller+equal-1
\]

Например, для nums = [1, 2, 5, 2, 3] и target = 2:
- Чисел меньше 2 — одно: 1.
- Чисел, равных 2, — два.
- Первый целевой индекс — 1.
- Следующий индекс — 2.
Ответ: [1, 2].

Это и будет оптимальное решение для данной задачи: один проход по массиву, без сортировки и без дополнительного массива.
3. Оптимальное решение на Java
Вариант для LeetCode: метод внутри класса Solution.

import java.util.ArrayList; // Импортируем ArrayList для хранения целевых индексов.
import java.util.List;      // Импортируем List — интерфейс списка.

class Solution { // Объявляем класс, который ожидает LeetCode.

    public List<Integer> targetIndices(int[] nums, int target) { // Принимаем массив и целевое число; возвращаем список индексов.

        int smaller = 0; // Счётчик элементов, которые меньше target.
        int equal = 0;   // Счётчик элементов, которые равны target.

        for (int num : nums) { // Перебираем каждый элемент исходного массива.
            if (num < target) { // Проверяем, меньше ли текущий элемент целевого числа.
                smaller++;      // Если меньше, увеличиваем счётчик меньших элементов.
            } else if (num == target) { // Иначе проверяем, равен ли элемент target.
                equal++;               // Если равен, увеличиваем счётчик целевых элементов.
            }
        }

        List<Integer> result = new ArrayList<>(); // Создаём пустой список для ответа.

        for (int i = 0; i < equal; i++) { // Выполняем цикл столько раз, сколько найдено target.
            result.add(smaller + i); // Добавляем очередной целевой индекс в возрастающем порядке.
        }

        return result; // Возвращаем список найденных индексов.
    }
}



4. Подробный комментарий к каждой части кода
Разберём, зачем нужна каждая строка и какую роль она играет в алгоритме.

Импорты
import java.util.ArrayList;
import java.util.List;


- ArrayList — реализация списка, в который можно динамически добавлять элементы.
- List<Integer> — интерфейс, описывающий список целых чисел. В Java для хранения чисел в коллекциях используем тип Integer, а не примитивный int.
Объявление метода
public List<Integer> targetIndices(int[] nums, int target)


- public — метод доступен извне класса.
- List<Integer> — метод возвращает список целочисленных индексов.
- targetIndices — имя метода, соответствующее условию LeetCode.
- int[] nums — входной массив.
- int target — число, индексы которого нужно найти.
Инициализация счётчиков
int smaller = 0;
int equal = 0;


Оба счётчика изначально равны нулю, поскольку мы ещё не обработали ни одного элемента.

Переменная smaller определяет, сколько элементов будет стоять перед target после сортировки.

Переменная equal определяет, сколько раз target встретился в массиве.

Первый цикл
for (int num : nums)


Это расширенный цикл for (for-each). Он последовательно получает каждое значение массива и помещает его в переменную num.

Например, для массива [1, 2, 5, 2, 3] переменная num по очереди примет значения 1, 2, 5, 2, 3.
if (num < target) {
    smaller++;
}


Если текущее число меньше целевого, увеличиваем smaller на единицу.

Оператор ++ увеличивает значение переменной на единицу. Например, если smaller = 1, после smaller++ значение станет 2.
else if (num == target) {
    equal++;
}


Если число не меньше target, проверяем, равно ли оно целевому числу. Если да, увеличиваем equal.

Обрати внимание: мы используем == для сравнения чисел, а = — для присваивания значения переменной.

Если число больше target, не происходит ничего: оно не влияет ни на количество меньших элементов, ни на количество целевых.

Создание списка ответа
List<Integer> result = new ArrayList<>();


Создаём пустой список, куда будем записывать найденные индексы.

Например, если целевое число встречается дважды и перед ним располагается один элемент, список впоследствии станет [1, 2].

Второй цикл
for (int i = 0; i < equal; i++) {
    result.add(smaller + i);
}


Цикл выполняется ровно equal раз.
- int i = 0 — начинаем с нуля.
- i < equal — продолжаем, пока i меньше количества целевых элементов.
- i++ — после каждой итерации увеличиваем i на единицу.
- result.add(smaller + i) — добавляем индекс в список.
Почему именно smaller + i? Потому что первый целевой элемент стоит после всех элементов, меньших target. Его индекс равен smaller. Каждый следующий целевой элемент занимает следующий индекс.

Возврат результата
return result;


Возвращаем сформированный список. Если equal = 0, второй цикл не выполнится ни разу, и метод вернёт пустой список.

6. Анализ временной и пространственной сложности
Пусть \(n\) — длина массива nums, а \(k\) — количество вхождений target.

Временная сложность — \(O(n)\)

Первый цикл проверяет каждый элемент ровно один раз: \(O(n)\). Второй цикл добавляет \(k\) индексов: \(O(k)\).

Итого \(O(n+k)=O(n)\), поскольку \(k\le n\).




Дополнительная память — \(O(k)\)

Используем два счётчика, которые занимают \(O(1)\) памяти, и список result, в котором хранится \(k\) индексов.

Итоговая дополнительная память — \(O(k)\), или \(O(n)\) в худшем случае.



Важно различать память, используемую самим алгоритмом, и память для ответа. Если учитывать только вспомогательную память, не считая возвращаемый список, она составляет \(O(1)\). Если учитывать весь результат, требуется \(O(k)\).

Для задачи, в которой нужно вернуть все индексы, это оптимальная асимптотическая сложность: мы должны прочитать массив, чтобы определить количество меньших и равных элементов, и сформировать список из \(k\) индексов.
7. Почему не нужно сортировать массив?
Сортировка — естественное решение, но здесь она не нужна.

Представим, что массив содержит следующие числа:
[7, 2, 4, 2, 9, 1]


Ищем target = 4.

Нам необязательно менять порядок элементов. Достаточно выяснить:
- Сколько чисел меньше 4? Три: 2, 2, 1.
- Сколько чисел равны 4? Одно.
Значит, после сортировки число 4 окажется на индексе 3.

Ответ:
[3]


Таким образом, мы получаем тот же результат, что и после сортировки, но тратим меньше времени.
8. Что важно запомнить для собеседования
1. Ищите свойства отсортированного массива. Все элементы меньше целевого значения будут стоять перед ним, а равные элементы образуют непрерывный диапазон.
2. Не выполняйте лишние операции. Если для ответа достаточно посчитать элементы, сортировка не нужна.
3. Используйте счётчики. Количество элементов, меньших target, сразу определяет начальный индекс целевого диапазона.
4. Учитывайте граничные случаи. Если target отсутствует, equal = 0, и метод вернёт []. Если все элементы равны target, ответом будут все индексы от 0 до nums.length - 1.
5. Оценивайте сложность всего алгоритма. Два последовательных цикла дают \(O(n)+O(k)=O(n)\), а не \(O(n^2)\).
Итог: для LeetCode 2089 рекомендую решение с двумя счётчиками. Оно не изменяет входной массив, не выполняет сортировку, работает за \(O(n)\) времени и использует \(O(k)\) памяти для списка ответа.
