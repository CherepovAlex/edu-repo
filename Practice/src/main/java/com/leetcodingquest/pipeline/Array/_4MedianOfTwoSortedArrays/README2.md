Почему простое объединение не подходит?
Самое очевидное решение — объединить два массива в один новый массив и отсортировать его (или слить, так как они уже отсортированы).

Сложность по времени: $O(m + n)$.
Требование задачи: $O(\log(m + n))$. Это означает, что мы не можем просматривать элементы по одному. Нам нужен бинарный поиск.
Идеально решение: Бинарный поиск по разрезам (Partitioning)
Мы хотим разделить объединенный отсортированный массив на две части (левую и правую) так, чтобы:

Количество элементов в левой части было равно количеству элементов в правой (или на 1 больше для нечетной длины).
Все элементы в левой части $\le$ всех элементов в правой части.
Медиана будет зависеть от максимального элемента в левой части и минимального в правой.

Алгоритм:
Работаем с более коротким массивом (nums1), чтобы снизить сложность поиска.
Делаем бинарный поиск по nums1 для нахождения позиции разреза (i).
Позиция разреза во втором массиве (j) вычисляется автоматически, чтобы общее количество элементов слева было правильным.
Проверяем условие: max(left_part) <= min(right_part).
Если nums1[i-1] > nums2[j], значит, разрез в nums1 слишком правый (элементы большие ушли вправо, должны были быть влево). Сдвигаем i влево.
Если nums2[j-1] > nums1[i], значит, разрез в nums1 слишком левый. Сдвигаем i вправо.
Если условие соблюдено, мы нашли медиану.
Реализация на Java

Применить
class Solution {
    public double findMedianSortedArrays(int[] nums1, int[] nums2) {
        // Убедимся, что nums1 - это меньший массив.
        // Это критично для обеспечения O(log(min(m, n)))
        if (nums1.length > nums2.length) {
            return findMedianSortedArrays(nums2, nums1);
        }
        int m = nums1.length;
        int n = nums2.length;
        
        // Диапазон для бинарного поиска индекса разбиения в nums1
        int low = 0;
        int high = m;
        
        while (low <= high) {
            // i - количество элементов в левой части из nums1
            // Мы берем половину от текущего диапазона, чтобы избежать переполнения int
            int partitionNums1 = (low + high) / 2;
            
            // j - количество элементов в левой части из nums2
            // Общее количество элементов в левой части должно быть (m + n + 1) / 2
            int partitionNums2 = (m + n + 1) / 2 - partitionNums1;
            
            // Если partitionNums1 == 0, значит в левой части нет элементов из nums1.
            // maxLeftNums1 должен быть "минус бесконечностью", чтобы он не влиял на сравнение
            double maxLeftNums1 = (partitionNums1 == 0) ? Integer.MIN_VALUE : nums1[partitionNums1 - 1];
            
            // Если partitionNums1 == m, значит все элементы nums1 в левой части.
            // minRightNums1 должен быть "плюс бесконечностью", чтобы он не влиял на сравнение
            double minRightNums1 = (partitionNums1 == m) ? Integer.MAX_VALUE : nums1[partitionNums1];
            
            // Аналогично для nums2
            double maxLeftNums2 = (partitionNums2 == 0) ? Integer.MIN_VALUE : nums2[partitionNums2 - 1];
            double minRightNums2 = (partitionNums2 == n) ? Integer.MAX_VALUE : nums2[partitionNums2];
            
            // Проверяем, нарушены ли условия упорядоченности
            if (maxLeftNums1 > minRightNums2) {
                // Элемент из левой части nums1 больше минимального элемента правой части nums2.
                // Значит, мы взяли слишком много элементов из nums1 в левую часть.
                // Нужно уменьшить partitionNums1 (двинуться влево)
                high = partitionNums1 - 1;
            } else if (maxLeftNums2 > minRightNums1) {
                // Элемент из левой части nums2 больше минимального элемента правой части nums1.
                // Значит, мы взяли слишком мало элементов из nums1 в левую часть (и слишком много из nums2).
                // Нужно увеличить partitionNums1 (двинуться вправо)
                low = partitionNums1 + 1;
            } else {
                // Идеальное разбиение найдено!
                // Вычисляем медиану
                if ((m + n) % 2 == 0) {
                    // Если общая длина четная, медиана - среднее арифметическое двух средних
                    return (Math.max(maxLeftNums1, maxLeftNums2) + Math.min(minRightNums1, minRightNums2)) / 2.0;
                } else {
                    // Если общая длина нечетная, медиана - максимум из левой части
                    return Math.max(maxLeftNums1, maxLeftNums2);
                }
            }
        }
        
        // Если цикл завершился, значит решение найдено на предыдущих шагах,
        // но формально это должно быть недостижимо при корректном вводе
        throw new IllegalArgumentException("Input arrays are not sorted or invalid.");
    }
}
Пошаговое объяснение строк кода
if (nums1.length > nums2.length): Проверяем, не длиннее ли первый массив. Если да, меняем их местами рекурсивным вызовом. Это гарантирует, что бинарный поиск будет проводиться по меньшему массиву, что экономит время.
int m = nums1.length; int n = nums2.length;: Сохраняем длины массивов для дальнейших вычислений.
int low = 0; int high = m;: Инициализируем границы бинарного поиска для индекса разбиения (partitionNums1). Мы можем выбрать от 0 элементов из nums1 в левую часть до всех m элементов.
while (low <= high): Начало цикла бинарного поиска.
int partitionNums1 = (low + high) / 2;: Находим середину текущего диапазона поиска. Это количество элементов из nums1, которые мы помещаем в левую половину объединенного массива.
int partitionNums2 = (m + n + 1) / 2 - partitionNums1;: Вычисляем, сколько элементов нужно взять из nums2 в левую половину, чтобы общее количество элементов слева было (m+n+1)/2. (m+n+1)/2 используется вместо (m+n)/2, чтобы для нечетных сумм левая часть имела на один элемент больше, что упрощает логику (так как медиана всегда будет max(leftPart)).
double maxLeftNums1 = ...: Находим максимальный элемент в левой части nums1. Если разбиение у самого начала (0), ставим MIN_VALUE, так как минимального элемента слева нет.
double minRightNums1 = ...: Находим минимальный элемент в правой части nums1. Если разбиение у самого конца (m), ставим MAX_VALUE, так как минимального элемента справа нет.
double maxLeftNums2 = ...: Аналогично для nums2.
double minRightNums2 = ...: Аналогично для nums2.
if (maxLeftNums1 > minRightNums2): Проверяем, не нарушен ли порядок. Если последний элемент слева в nums1 больше первого элемента справа в nums2, значит, мы взяли слишком много из nums1.
high = partitionNums1 - 1;: Сдвигаем правую границу поиска влево, чтобы уменьшить количество элементов из nums1 в левой части.
else if (maxLeftNums2 > minRightNums1): Если последний элемент слева в nums2 больше первого элемента справа в nums1, значит, мы взяли слишком мало из nums1 (слишком много из nums2).
low = partitionNums1 + 1;: Сдвигаем левую границу поиска вправо, чтобы увеличить количество элементов из nums1 в левой части.
else { ... }: Если ни одно из условий не выполнено, значит, разбиение правильное. maxLeftNums1 и maxLeftNums2 — это два "средних" элемента (или одно).
if ((m + n) % 2 == 0): Проверяем, четная ли общая длина массивов.
return (Math.max(...) + Math.min(...)) / 2.0;: Если длина четная, медиана — среднее двух средних элементов.
return Math.max(maxLeftNums1, maxLeftNums2);: Если длина нечетная, медиана — максимальный элемент из левой части (который содержит на один элемент больше).
Пошаговый разбор Примеров
Пример 1: nums1 = [1, 3], nums2 = [2]
m = 2, n = 1. m > n ложно, работаем как есть. low = 0, high = 2.

Итерация 1:

partitionNums1 = (0 + 2) / 2 = 1.
Берем 1 элемент из nums1 в левую часть: [1].
partitionNums2 = (2 + 1 + 1) / 2 - 1 = 2 - 1 = 1.
Берем 1 элемент из nums2 в левую часть: [2].
Левая часть объединенного: [1] (из nums1) и [2] (из nums2).
maxLeftNums1 = nums1[0] = 1.
minRightNums1 = nums1[1] = 3.
maxLeftNums2 = nums2[0] = 2.
minRightNums2 = nums2[1] (выход за пределы) = MAX_VALUE.
Проверки:
maxLeftNums1 (1) > minRightNums2 (MAX_VALUE)? Нет.
maxLeftNums2 (2) > minRightNums1 (3)? Нет.
Условие соблюдено!
Общая длина 3 (нечетная).
Возвращаем Math.max(maxLeftNums1, maxLeftNums2) = Math.max(1, 2) = 2.
Результат: 2.0.
Пример 2: nums1 = [1, 2], nums2 = [3, 4]
m = 2, n = 2. low = 0, high = 2.

Итерация 1:

partitionNums1 = (0 + 2) / 2 = 1.
Из nums1 в левую: [1].
partitionNums2 = (2 + 2 + 1) / 2 - 1 = 2 - 1 = 1.
Из nums2 в левую: [3].
Левая часть: [1] (из nums1) и [3] (из nums2).
maxLeftNums1 = 1.
minRightNums1 = 2.
maxLeftNums2 = 3.
minRightNums2 = 4.
Проверки:
1 > 4? Нет.
3 > 2? Да! (maxLeftNums2 > minRightNums1).
Значит, partitionNums1 слишком мал.
low = 1 + 1 = 2. high остается 2.
Итерация 2:

partitionNums1 = (2 + 2) / 2 = 2.
Из nums1 в левую: [1, 2].
partitionNums2 = (2 + 2 + 1) / 2 - 2 = 2 - 2 = 0.
Из nums2 в левую: [].
Левая часть: [1, 2] (из nums1) и [] (из nums2).
maxLeftNums1 = 2.
minRightNums1 = MAX_VALUE (так как partitionNums1 == m).
maxLeftNums2 = MIN_VALUE (так как partitionNums2 == 0).
minRightNums2 = 3.
Проверки:
2 > 3? Нет.
MIN_VALUE > MAX_VALUE? Нет.
Условие соблюдено!
Общая длина 4 (четная).
Возвращаем (Math.max(2, MIN_VALUE) + Math.min(MAX_VALUE, 3)) / 2.0.
Math.max(2, -∞) = 2.
Math.min(+∞, 3) = 3.
(2 + 3) / 2.0 = 2.5.
Результат: 2.5.
Сложность
Время: $O(\log(\min(m, n)))$. Мы делаем бинарный поиск по меньшему массиву.
Пространство: $O(1)$. Мы используем только переменные, не создаем новых массивов.
Если у тебя есть вопросы по каким-то шагам или хочешь разобрать граничный случай (например, когда один из массивов пуст), дай знать!
