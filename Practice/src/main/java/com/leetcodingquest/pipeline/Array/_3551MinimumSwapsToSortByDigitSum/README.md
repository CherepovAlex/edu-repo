LeetCode 3551 — Минимальное количество перестановок для сортировки по сумме цифр
Разберём задачу как полноценный урок по Java: от понимания условия до оптимального алгоритма, комментариев к каждой строке кода и пошагового выполнения всех трёх примеров.
Главная идея задачи: сначала нужно определить правильный порядок элементов, а затем найти минимальное количество обменов, чтобы преобразовать исходный массив в этот порядок.
Важно: недостаточно просто отсортировать массив и посчитать, сколько элементов изменили позиции. Один обмен может одновременно поставить на правильные места два элемента, а в некоторых случаях — несколько шагов перестановки можно сократить за счёт правильного выбора пар.
1. Что требуется сделать
Дан массив различных положительных целых чисел nums.
Нужно выполнить две логические операции:
1. Отсортировать числа по сумме их цифр в порядке возрастания.
2. Если суммы цифр одинаковые, поставить первым меньшее число.
После этого нужно вернуть минимальное количество обменов двух элементов, необходимых для получения отсортированного массива.
Например, для массива:
nums = [37, 100]


Суммы цифр:
- 37: \(3 + 7 = 10\)
- 100: \(1 + 0 + 0 = 1\)
Поэтому правильный порядок — [100, 37]. Исходный массив можно привести к нему одним обменом.
Ответ: 1.
2. Какой алгоритм будем использовать
Оптимальное решение состоит из двух этапов.

Этап 1. Сортировка
Создаём копию массива и сортируем её по сумме цифр, а при равенстве сумм — по самому числу.




Этап 2. Подсчёт обменов
Сравниваем исходный массив с отсортированным. Если элемент находится не на своём месте, меняем его с элементом, который должен стоять на этой позиции, и увеличиваем счётчик.



Для второго этапа удобно использовать массив position, в котором храним исходную позицию каждого числа. Благодаря этому мы можем за один обмен ставить на нужное место конкретный элемент, не выполняя линейный поиск по массиву.
Почему это оптимально? Каждый обмен исправляет одну неправильную позицию и, возможно, сразу вторую. Более строгое доказательство минимальности разберём после кода.
3. Полное решение на Java с комментариями к каждой строке
Используем HashMap, чтобы быстро находить текущую позицию нужного числа. Сам массив сортируем отдельно, чтобы сохранить исходный порядок для сравнения.

import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;

class Solution {

    // Метод возвращает сумму цифр положительного числа.
    private int digitSum(int num) {
        int sum = 0;                  // Переменная для накопления суммы цифр.

        while (num > 0) {             // Пока в числе остаются цифры.
            sum += num % 10;          // Берём последнюю цифру и добавляем к сумме.
            num /= 10;                // Удаляем последнюю цифру числа.
        }

        return sum;                   // Возвращаем вычисленную сумму цифр.
    }

    // Метод вычисляет минимальное количество обменов.
    public int minSwaps(int[] nums) {

        int n = nums.length;          // Сохраняем длину исходного массива.

        Integer[] sorted = new Integer[n]; // Создаём массив для сортировки.

        for (int i = 0; i < n; i++) { // Перебираем все элементы nums.
            sorted[i] = nums[i];      // Копируем число в новый массив.
        }

        // Сортируем по сумме цифр, затем по значению самого числа.
        Arrays.sort(sorted, (a, b) -> {
            int sumA = digitSum(a);   // Вычисляем сумму цифр числа a.
            int sumB = digitSum(b);   // Вычисляем сумму цифр числа b.

            if (sumA != sumB) {       // Если суммы цифр различаются,
                return sumA - sumB;   // меньшая сумма должна идти первой.
            }

            return Integer.compare(a, b); // При равных суммах сравниваем числа.
        });

        // Храним текущее положение каждого числа в изменяемом nums.
        Map<Integer, Integer> position = new HashMap<>();

        for (int i = 0; i < n; i++) { // Перебираем исходный массив.
            position.put(nums[i], i); // Запоминаем индекс каждого числа.
        }

        int swaps = 0;                // Счётчик выполненных обменов.

        for (int i = 0; i < n; i++) { // Проверяем позиции слева направо.

            if (nums[i] == sorted[i]) { // Если число уже на нужном месте,
                continue;               // переходим к следующей позиции.
            }

            int target = sorted[i];    // Число, которое должно стоять здесь.
            int j = position.get(target); // Находим его текущий индекс.
            int current = nums[i];     // Сохраняем число, стоящее здесь сейчас.

            nums[i] = target;          // Ставим целевое число на нужное место.
            nums[j] = current;         // Перемещаем прежнее число на индекс j.

            position.put(target, i);   // Обновляем позицию целевого числа.
            position.put(current, j);  // Обновляем позицию второго числа.

            swaps++;                   // Учитываем один выполненный обмен.
        }

        return swaps;                  // Возвращаем минимальное число обменов.
    }
}



Этот код предназначен для отправки в LeetCode. Платформа сама вызывает метод minSwaps, передавая ему массив nums.
4. Как работает вычисление суммы цифр
Разберём вспомогательный метод digitSum() отдельно:
private int digitSum(int num) {
    int sum = 0;

    while (num > 0) {
        sum += num % 10;
        num /= 10;
    }

    return sum;
}


Возьмём число 437.
Шаг	num до операции	num % 10	sum после сложения	num /= 10
1	437	7	7	43
2	43	3	10	4
3	4	4	14	0
После третьего шага условие num > 0 перестаёт выполняться. Метод возвращает 14.
Что здесь важно запомнить:
- num % 10 — остаток от деления на 10, то есть последняя цифра числа.
- num /= 10 — целочисленное деление на 10, которое удаляет последнюю цифру.
- sum += ... — сокращённая запись sum = sum + ....
Нули также обрабатываются корректно. Например, для 100 алгоритм последовательно извлечёт цифры 0, 0 и 1, получив сумму 1.
5. Как работает сортировка
Главная часть компаратора:
Arrays.sort(sorted, (a, b) -> {
    int sumA = digitSum(a);
    int sumB = digitSum(b);

    if (sumA != sumB) {
        return sumA - sumB;
    }

    return Integer.compare(a, b);
});


Компаратор определяет, какое из двух чисел должно стоять раньше.
Рассмотрим числа 43 и 16:
- Сумма цифр 43 равна 7.
- Сумма цифр 16 равна 7.
Суммы совпали, поэтому сравниваем сами числа: 16 меньше 43. Следовательно, 16 должно стоять раньше 43.
А если сравнить 37 и 100:
- Сумма цифр 37 равна 10.
- Сумма цифр 100 равна 1.
В этом случае первым должно идти 100, потому что сумма его цифр меньше.
Таким образом, мы соблюдаем оба условия задачи.

9. Почему алгоритм находит именно минимальное количество обменов?
Это самый важный теоретический вопрос задачи.
Представим, что после сортировки мы получили:
nums   = [18, 43, 34, 16]
sorted = [16, 34, 43, 18]


Чтобы отсортировать массив, элементы должны переместиться на определённые позиции. Эти перемещения образуют циклы.
В нашем примере:
- 18 и 16 должны поменяться позициями.
- 43 и 34 тоже должны поменяться позициями.
Получаются два независимых цикла длины 2. Каждый такой цикл требует одного обмена. Поэтому ответ равен 2.
В общем случае для цикла длины \(k\) требуется минимум \(k-1\) обменов.
Например, если три элемента должны циклически переместиться на новые позиции, одного обмена недостаточно: после первого обмена один из этих трёх элементов всё ещё останется не на своём месте. Потребуются два обмена.
Для нескольких циклов минимальное число обменов равно:
\[
\text{swaps}=\sum_{\text{циклы}}(k-1)
\]

Наш алгоритм достигает этого минимума: на каждой неправильной позиции он сразу находит нужный элемент и ставит его туда. При этом уже исправленные позиции больше не меняются.
Почему это работает: обмен двух элементов может исправить не более двух позиций, а обмен с элементом, который должен стоять на текущем месте, эффективно устраняет одну часть соответствующего цикла. Таким образом, алгоритм не выполняет лишних обменов.
10. Сложность алгоритма
Пусть \(n\) — количество элементов массива, а \(d\) — максимальное количество цифр в одном числе.
Операция	Временная сложность
Копирование массива	\(O(n)\)
Сортировка	\(O(n\log n \cdot d)\)
Создание HashMap	\(O(n)\) в среднем
Подсчёт обменов	\(O(n)\) в среднем
Поскольку по условию nums[i] <= 10^9, каждое число содержит не более 10 цифр. Поэтому \(d\) ограничено небольшой константой.
Итоговая сложность:
Время
\(O(n\log n)\)


Дополнительная память
\(O(n)\)


Дополнительная память нужна для отсортированной копии массива и HashMap, хранящей текущие позиции элементов.
Для ограничения \(n \le 10^5\) это эффективное решение.
11. Что нужно запомнить перед собеседованием
- digitSum() — вычисляет сумму цифр числа с помощью % 10 и / 10.
- Arrays.sort() с компаратором — реализует сортировку по двум критериям: сумма цифр, затем само число.
- HashMap<Integer, Integer> — позволяет быстро находить текущую позицию элемента.
- continue — пропускает элементы, которые уже находятся на правильном месте.
- Жадный обмен — помещает нужный элемент на текущую позицию и не трогает уже отсортированную часть массива.
Есть и другой классический способ решения подобных задач — представить перестановку как набор циклов и вычислить сумму \(k-1\) для каждого цикла. Но в нашем решении это не требуется: прямые обмены с использованием карты позиций реализуют тот же минимальный принцип.
Главное отличие этой задачи от обычной сортировки: нужно не просто получить отсортированный массив, а вычислить минимальное количество обменов, необходимых для его получения.
