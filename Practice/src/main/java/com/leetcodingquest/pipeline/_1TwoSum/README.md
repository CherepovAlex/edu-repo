LeetCode №1 — Two Sum («Две суммы»): подробный урок по Java
Разберём задачу так, как её объясняют на занятии по Java-разработке: сначала поймём условие, затем рассмотрим простое решение, перейдём к оптимальному алгоритму с HashMap, построчно разберём код и вручную выполним все три примера.
Наша цель — найти оптимальное решение со сложностью по времени \(O(n)\) и дополнительной памяти \(O(n)\).
1. Понимаем условие задачи
Нам даны два объекта:
- nums — массив целых чисел.
- target — число, которое должно получиться при сложении двух элементов массива.
Нужно найти индексы двух элементов, сумма которых равна target.

Проверяем: \(2+7=9\).
Ответ: [0, 1] — индексы элементов со значениями 2 и 7.

Обратите внимание на важный момент: возвращать нужно индексы, а не сами числа.
Если вернуть [2, 7], это будет неправильный ответ. Правильный ответ — [0, 1].
Что ещё важно учитывать?
1. Индексация массива в Java начинается с нуля.
2. Нельзя использовать один элемент дважды.
3. В условии гарантируется ровно одно правильное решение.
4. Числа могут повторяться, как в примере [3, 3].
5. Ответ можно вернуть в любом порядке.

2. Простой алгоритм: перебор всех пар
Прежде чем переходить к оптимальному решению, посмотрим, как можно решить задачу самым очевидным способом.
Идея простая: берём первый элемент и складываем его с каждым следующим. Затем берём второй элемент и повторяем действия для оставшихся элементов. Так продолжаем, пока не найдём нужную пару.
Например, для массива nums = [2, 7, 11, 15] и target = 9:
Первый индекс	Второй индекс	Вычисление	Результат
0	1	2 + 7 = 9	Найдена пара
—	—	—	Останавливаемся
Простейшая реализация на Java:
class Solution {
    public int[] twoSum(int[] nums, int target) {
        for (int i = 0; i < nums.length; i++) {
            for (int j = i + 1; j < nums.length; j++) {
                if (nums[i] + nums[j] == target) {
                    return new int[]{i, j};
                }
            }
        }
        return new int[]{};
    }
}


Почему это решение не оптимально?
Здесь используются два вложенных цикла:
- Внешний цикл перебирает элементы массива.
- Внутренний цикл проверяет все элементы после текущего.
В худшем случае количество проверок растёт примерно пропорционально квадрату длины массива.
Временная сложность — \(O(n^2)\).
Дополнительная память — \(O(1)\), поскольку алгоритм использует лишь несколько переменных, не считая массива результата.
При массиве из 10 000 элементов количество проверок может достигать:
\[
\frac{n(n-1)}{2}
=
\frac{10000\cdot9999}{2}
=
49\,995\,000
\]

Можно ли сделать лучше? Да. Для этого воспользуемся HashMap.

3. Оптимальный алгоритм: HashMap
Главная идея
Вместо того чтобы каждый раз искать второе число перебором, мы можем запоминать уже встреченные числа и их индексы.
Допустим, мы рассматриваем число 2, а target = 9.
Чтобы получить 9, нам нужно найти:
\[
9-2=7
\]

Число 7 называется дополнением — именно его нам не хватает до целевой суммы.
Если число 7 уже встречалось, мы сразу получаем ответ. Если нет, сохраняем число 2 и его индекс в HashMap, а затем переходим к следующему элементу.

Когда дойдём до числа 7, найдём ранее сохранённое число 2 и вернём индексы 0 и 1.

Что такое HashMap?
HashMap — это структура данных Java, которая хранит пары «ключ — значение».
В нашей задаче:
- Ключ — число из массива.
- Значение — индекс, по которому это число находится.
Например, после обработки первых двух чисел массива [2, 7, 11, 15] карта может выглядеть так:
Ключ — число	Значение — индекс
2	0
7	1
Объявление такой карты:
Map<Integer, Integer> map = new HashMap<>();


Здесь первый Integer означает тип ключа, а второй — тип значения.
Почему именно HashMap? Потому что в среднем поиск ключа, добавление и получение значения выполняются за \(O(1)\). Благодаря этому нам не требуется каждый раз проходить по всему массиву.

4. Полное оптимальное решение на Java
Это решение можно отправить непосредственно в LeetCode.

import java.util.HashMap;
import java.util.Map;

class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> map = new HashMap<>();

        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];

            if (map.containsKey(complement)) {
                return new int[]{map.get(complement), i};
            }

            map.put(nums[i], i);
        }

        return new int[]{};
    }
}



В LeetCode обычно достаточно предоставить класс Solution: платформа самостоятельно вызывает метод twoSum. Импорты нужны для использования HashMap и Map.
Теперь разберём каждую строку.

10. Анализ сложности алгоритма
Теперь оценим решение с точки зрения алгоритмической сложности.
Временная сложность
Основной цикл проходит по массиву максимум один раз.
Внутри цикла выполняются операции HashMap:
- вычисление дополнения;
- containsKey();
- get() при нахождении ответа;
- put() при отсутствии ответа.
Операции HashMap в среднем выполняются за \(O(1)\).
Следовательно, ожидаемая временная сложность:
\[
\boxed{O(n)}
\]

Это значительно лучше, чем \(O(n^2)\) у двойного цикла.
Пространственная сложность
В худшем случае мы можем сохранить в карте почти все элементы массива до нахождения пары.
Количество записей пропорционально длине массива:
\[
\boxed{O(n)}
\]

Мы сознательно используем дополнительную память, чтобы сократить время поиска.
Важно: \(O(n)\) — это сложность дополнительной памяти. Возвращаемый массив из двух индексов занимает постоянное количество памяти, \(O(1)\), и не меняет общую оценку.
Сравнение алгоритмов
Характеристика	Два вложенных цикла	HashMap
Время	\(O(n^2)\)	\(O(n)\) в среднем
Дополнительная память	\(O(1)\)	\(O(n)\)
Перебор пар	Да	Нет
Подходит для больших массивов	Менее эффективно	Да
Уточнение: для HashMap оценка \(O(n)\) является ожидаемой при обычном поведении хеш-таблицы. В худших теоретических условиях отдельные операции могут работать медленнее.

12. Что нужно запомнить для собеседования по Java
Для задачи Two Sum важно понимать не только код, но и причину выбора алгоритма.
- HashMap позволяет хранить число и его индекс.
- Дополнение вычисляется по формуле target - nums[i].
- Проверка выполняется до добавления текущего элемента, чтобы не использовать его дважды.
- Временная сложность — \(O(n)\) в среднем.
- Дополнительная пространственная сложность — \(O(n)\).
Если на собеседовании спросят, как улучшить решение с \(O(n^2)\), можно ответить так:
Я использую HashMap, где ключом является значение элемента, а значением — его индекс. Для каждого элемента вычисляю дополнение target - nums[i] и проверяю, присутствует ли оно в карте. Если присутствует, возвращаю индекс дополнения и индекс текущего элемента. В противном случае сохраняю текущий элемент в карте. Благодаря этому каждый элемент обрабатывается один раз, а ожидаемая временная сложность составляет \(O(n)\).

Это и есть основная идея оптимального решения LeetCode №1 Two Sum.
