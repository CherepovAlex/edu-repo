# LeetCode 7 — Перевернуть целое число (Reverse Integer)

Подробный разбор решения задачи на Java: идея алгоритма, код с комментариями к каждой строке, пошаговые вычисления для трёх примеров, проверка переполнения и оценка сложности.

## Условие задачи

Дано 32-разрядное целое число со знаком `x`. Необходимо вернуть число, полученное перестановкой его цифр в обратном порядке.

Если после переворота число выходит за диапазон 32-разрядных целых чисел со знаком, необходимо вернуть `0`.

Допустимый диапазон:

\[
-2^{31} \le x \le 2^{31}-1
\]

В Java границы типа `int`:

| Константа | Значение |
|---|---:|
| `Integer.MIN_VALUE` | `-2147483648` |
| `Integer.MAX_VALUE` | `2147483647` |

**Ограничение:** нельзя использовать 64-разрядный тип `long` даже для проверки переполнения.

### Примеры

| Пример | Входные данные | Результат |
|---|---|---:|
| 1 | `x = 123` | `321` |
| 2 | `x = -123` | `-321` |
| 3 | `x = 120` | `21` |

В третьем примере ведущий ноль результата не сохраняется: число `021` равно `21`.

Дополнительный пример переполнения: `x = 1534236469`. После переворота получится `9646324351`, что выходит за диапазон `int`, поэтому ответ — `0`.

---

## 1. Идея решения

Будем извлекать последнюю цифру исходного числа и добавлять её в конец нового числа.

Для этого используются две операции:

- `x % 10` — получить последнюю цифру числа.
- `x / 10` — удалить последнюю цифру. При делении целых чисел Java отбрасывает дробную часть в сторону нуля.

Например, для `123`:

| Шаг | Текущий `x` | `digit = x % 10` | `reversed = reversed * 10 + digit` |
|---|---:|---:|---:|
| Начало | `123` | — | `0` |
| 1 | `123` | `3` | `3` |
| 2 | `12` | `2` | `32` |
| 3 | `1` | `1` | `321` |

На каждой итерации сначала извлекаем последнюю цифру, затем убираем её из `x`, а после этого добавляем её к `reversed`.

Отрицательные числа обрабатываются тем же способом. Например, в Java `-123 % 10 == -3`, а `-123 / 10 == -12`. Поэтому знак минус сохраняется автоматически.

Главная сложность — **не допустить переполнения `int`**. Перед вычислением `reversed * 10 + digit` проверяем, не выйдет ли будущий результат за допустимые границы.

---

## 2. Решение на Java

Ниже приведён полный код, совместимый с шаблоном LeetCode. Комментарий есть у каждой строки, включая проверки переполнения.

```java
class Solution { // Объявляем класс Solution, который требуется на LeetCode.
    public int reverse(int x) { // Объявляем метод, переворачивающий число x.
        int reversed = 0; // Храним число, которое постепенно собираем в обратном порядке.

        while (x != 0) { // Повторяем действия, пока в исходном числе остаются цифры.
            int digit = x % 10; // Извлекаем последнюю цифру исходного числа.
            x /= 10; // Удаляем последнюю цифру из исходного числа.

            // Проверяем, не приведёт ли добавление цифры к положительному переполнению.
            if (reversed > Integer.MAX_VALUE / 10
                    || (reversed == Integer.MAX_VALUE / 10 && digit > 7)) {
                return 0; // Возвращаем 0, если результат выйдет за верхнюю границу int.
            }

            // Проверяем, не приведёт ли добавление цифры к отрицательному переполнению.
            if (reversed < Integer.MIN_VALUE / 10
                    || (reversed == Integer.MIN_VALUE / 10 && digit < -8)) {
                return 0; // Возвращаем 0, если результат выйдет за нижнюю границу int.
            }

            reversed = reversed * 10 + digit; // Добавляем извлечённую цифру в конец результата.
        }

        return reversed; // Возвращаем перевёрнутое число после обработки всех цифр.
    }
}
```

### Как работает основной цикл

В каждой итерации выполняются три действия:

1. `digit = x % 10` — извлекаем последнюю цифру.
2. `x /= 10` — удаляем последнюю цифру из исходного числа.
3. `reversed = reversed * 10 + digit` — добавляем извлечённую цифру в конец результата.

Например, если `reversed = 32` и `digit = 1`, то:

\[
32 \cdot 10 + 1 = 321
\]

Цикл заканчивается, когда `x` становится равным `0`.

---

## 3. Почему проверка переполнения устроена именно так?

Тип `int` хранит значения только от `-2147483648` до `2147483647`.

Перед операцией

```java
reversed = reversed * 10 + digit;
```

нужно убедиться, что новое значение останется в этом диапазоне. Проверка выполняется **до умножения на 10**, потому что после переполнения значение уже будет некорректным.

### Проверка верхней границы

```java
if (reversed > Integer.MAX_VALUE / 10
        || (reversed == Integer.MAX_VALUE / 10 && digit > 7)) {
    return 0;
}
```

Целочисленное деление даёт:

```text
Integer.MAX_VALUE / 10 = 214748364
```

- Если `reversed > 214748364`, умножение на 10 уже превысит верхнюю границу `int`.
- Если `reversed == 214748364`, последняя цифра должна быть не больше `7`, иначе итог превысит `2147483647`.

### Проверка нижней границы

```java
if (reversed < Integer.MIN_VALUE / 10
        || (reversed == Integer.MIN_VALUE / 10 && digit < -8)) {
    return 0;
}
```

Здесь:

```text
Integer.MIN_VALUE / 10 = -214748364
```

- Если `reversed < -214748364`, умножение на 10 выйдет за нижнюю границу.
- Если `reversed == -214748364`, последняя цифра должна быть не меньше `-8`, чтобы итог не оказался меньше `-2147483648`.

Пороговые цифры `7` и `-8` взяты из последних цифр границ типа `int`.

## 4. Пошаговый разбор примеров

### Пример 1: `x = 123`

**Ожидаемый результат: `321`.**

Начальные значения:

```text
x = 123
reversed = 0
```

| Итерация | `digit = x % 10` | Новое `x = x / 10` | Новое `reversed` |
|---|---:|---:|---:|
| Начало | — | `123` | `0` |
| 1 | `3` | `12` | `3` |
| 2 | `2` | `1` | `32` |
| 3 | `1` | `0` | `321` |

**Итерация 1**

- `digit = 123 % 10 = 3`.
- `x = 123 / 10 = 12`.
- `reversed = 0 * 10 + 3 = 3`.

**Итерация 2**

- `digit = 12 % 10 = 2`.
- `x = 12 / 10 = 1`.
- `reversed = 3 * 10 + 2 = 32`.

**Итерация 3**

- `digit = 1 % 10 = 1`.
- `x = 1 / 10 = 0`.
- `reversed = 32 * 10 + 1 = 321`.

Поскольку `x == 0`, цикл завершается, а метод возвращает `321`.

**Ответ: `321`.**

### Пример 2: `x = -123`

**Ожидаемый результат: `-321`.**

Начальные значения:

```text
x = -123
reversed = 0
```

| Итерация | `digit = x % 10` | Новое `x = x / 10` | Новое `reversed` |
|---|---:|---:|---:|
| Начало | — | `-123` | `0` |
| 1 | `-3` | `-12` | `-3` |
| 2 | `-2` | `-1` | `-32` |
| 3 | `-1` | `0` | `-321` |

**Итерация 1**

- `digit = -123 % 10 = -3`.
- `x = -123 / 10 = -12`.
- `reversed = 0 * 10 + (-3) = -3`.

**Итерация 2**

- `digit = -12 % 10 = -2`.
- `x = -12 / 10 = -1`.
- `reversed = -3 * 10 + (-2) = -32`.

**Итерация 3**

- `digit = -1 % 10 = -1`.
- `x = -1 / 10 = 0`.
- `reversed = -32 * 10 + (-1) = -321`.

В Java целочисленное деление округляет к нулю: например, `-123 / 10` равно `-12`, а не `-13`. Знак минус сохраняется автоматически — обрабатывать его отдельно не нужно.

**Ответ: `-321`.**

### Пример 3: `x = 120`

**Ожидаемый результат: `21`.**

Начальные значения:

```text
x = 120
reversed = 0
```

| Итерация | `digit = x % 10` | Новое `x = x / 10` | Новое `reversed` |
|---|---:|---:|---:|
| Начало | — | `120` | `0` |
| 1 | `0` | `12` | `0` |
| 2 | `2` | `1` | `2` |
| 3 | `1` | `0` | `21` |

**Итерация 1**

- `digit = 120 % 10 = 0`.
- `x = 120 / 10 = 12`.
- `reversed = 0 * 10 + 0 = 0`.

**Итерация 2**

- `digit = 12 % 10 = 2`.
- `x = 12 / 10 = 1`.
- `reversed = 0 * 10 + 2 = 2`.

**Итерация 3**

- `digit = 1 % 10 = 1`.
- `x = 1 / 10 = 0`.
- `reversed = 2 * 10 + 1 = 21`.

Начальный ноль не сохраняется, потому что результат хранится в числовой переменной типа `int`. Число `021` при обычной десятичной записи равно `21`.

**Ответ: `21`.**

## 5. Дополнительная проверка переполнения

Рассмотрим входное значение:

```text
x = 1534236469
```

Его перевёрнутая запись:

```text
9646324351
```

Но максимальное значение `int` — `2147483647`, поэтому перевёрнутое число не помещается в тип.

Алгоритм проверяет границы на каждой итерации **до** вычисления `reversed * 10 + digit`. Как только следующий шаг гарантированно приведёт к переполнению, метод возвращает `0`.

Это позволяет корректно обработать переполнение без `long`, строк и других дополнительных структур данных.

---

## 6. Сложность алгоритма

Пусть `n` — количество цифр во входном числе.

- **Временная сложность:** `O(n)`, поскольку каждая цифра обрабатывается ровно один раз. Эквивалентная запись для числа по его величине — `O(log10(|x|))` при `|x| > 0`.
- **Дополнительная пространственная сложность:** `O(1)`, потому что используются только несколько переменных типа `int`.

Для 32-разрядного целого числа цикл выполняется не более 10 раз.

---

## 7. Итог

Запомните три основных принципа:

1. `x % 10` извлекает последнюю цифру.
2. `x / 10` удаляет последнюю цифру, а `reversed * 10 + digit` добавляет её в конец результата.
3. Проверку переполнения нужно выполнять **до** умножения на 10. Для этого сравниваем результат с `Integer.MAX_VALUE / 10` и `Integer.MIN_VALUE / 10`, а при равенстве проверяем последнюю цифру.

Решение работает за линейное время относительно количества цифр и использует постоянную дополнительную память. Оно соблюдает условие задачи и не использует `long`.
