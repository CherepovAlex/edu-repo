Приветствую! Как преподаватель курса по Java, я рад помочь вам разобраться в этой классической задаче. 
Задача "Reverse Integer" (Перевернуть целое число) — это отличный тренажер для понимания арифметики целых чисел, 
работы с остатками от деления и, что самое важное, **обработки переполнения (overflow)**.

Давайте разберем всё по шагам.

### 1. Стратегия решения

Самый интуитивный способ — превратить число в строку, перевернуть строку и снова превратить её в число. 
**НО!** В условии задачи есть важное ограничение: *"Предполагается, что среда не позволяет хранить 
64-разрядные целые числа"*. Это значит, что мы **не можем** использовать `long` для промежуточных вычислений, 
чтобы проверить переполнение. Мы должны работать только с `int`.

Поэтому мы будем использовать **арифметический подход**:
1.  Выделять последнюю цифру числа с помощью оператора остатка от деления `% 10`.
2.  "Отрезать" последнюю цифру числа с помощью целочисленного деления `/ 10`.
3.  Прибавлять выделенную цифру к результату, предварительно умножив текущий результат на 10.

**Главная сложность:** Перед тем как умножить текущий результат на 10 и добавить новую цифру, нужно проверить, 
не выйдет ли новое число за границы `int` (от `-2^31` до `2^31 - 1`). Если выйдет — возвращаем 0.

### 2. Алгоритм проверки переполнения

Диапазон `int`:
*   Минимум: `-2,147,483,648` (`Integer.MIN_VALUE`)
*   Максимум: `2,147,483,647` (`Integer.MAX_VALUE`)

Пусть у нас есть текущий результат `rev`. Мы хотим сделать: `rev = rev * 10 + pop`.
Чтобы проверить, не переполнится ли это, мы можем проверить условия *до* умножения:

*   **Для положительного числа:** Если `rev > Integer.MAX_VALUE / 10` (то есть больше 214,748,364), 
то при умножении на 10 мы точно выйдем за пределы. Если `rev == Integer.MAX_VALUE / 10`, то новая цифра `pop` 
не должна быть больше 7 (так как максимальная последняя цифра MAX_VALUE — 7).
*   **Для отрицательного числа:** Если `rev < Integer.MIN_VALUE / 10` (то есть меньше -214,748,364), 
то переполнение. Если `rev == Integer.MIN_VALUE / 10`, то новая цифра `pop` не должна быть меньше -8 
(так как минимальная последняя цифра MIN_VALUE — 8, но так как мы работаем с модулями или просто сравниваем, 
важно помнить, что `MIN_VALUE` заканчивается на 8).

*Примечание:* В реализации мы будем использовать переменную `rev` как аккумулятор. Знак числа будет обрабатываться 
автоматически, так как Java сохраняет знак при операциях `%` и `/`.

### 3. Код решения с комментариями к каждой строке

```java
class Solution {
    public int reverse(int x) {
        // Инициализируем переменную для хранения перевернутого числа.
        // Начальное значение 0.
        int rev = 0;
        
        // Цикл выполняется, пока x не станет равным 0.
        // Это означает, что мы обработали все цифры исходного числа.
        while (x != 0) {
            // Извлекаем последнюю цифру числа x.
            // Оператор % 10 возвращает остаток от деления на 10.
            // Например, если x = 123, то pop = 3.
            // Если x = -123, то pop = -3 (Java сохраняет знак при остатке).
            int pop = x % 10;
            
            // "Отрезаем" последнюю цифру от x.
            // Оператор / 10 выполняет целочисленное деление.
            // Например, если x = 123, то x становится 12.
            // Если x = -123, то x становится -12.
            x /= 10;
            
            // ПРОВЕРКА НА ПЕРЕПОЛНЕНИЕ (OVERFLOW CHECK)
            // Мы не можем просто сделать rev = rev * 10 + pop, 
            // потому что это может выйти за пределы int.
            
            // Проверяем, не выйдет ли новое значение за максимальную границу Integer.MAX_VALUE (2147483647)
            // Если rev больше, чем 214748364 (MAX_VALUE / 10), то умножение на 10 гарантированно приведет к переполнению.
            if (rev > Integer.MAX_VALUE / 10 || (rev == Integer.MAX_VALUE / 10 && pop > 7)) {
                // Если переполнение возможно, возвращаем 0, как требует условие задачи.
                return 0;
            }
            
            // Проверяем, не выйдет ли новое значение за минимальную границу Integer.MIN_VALUE (-2147483648)
            // Если rev меньше, чем -214748364 (MIN_VALUE / 10), то умножение на 10 гарантированно приведет к переполнению.
            if (rev < Integer.MIN_VALUE / 10 || (rev == Integer.MIN_VALUE / 10 && pop < -8)) {
                // Если переполнение возможно, возвращаем 0.
                return 0;
            }
            
            // Обновляем перевернутое число.
            // Умножаем текущий результат на 10, чтобы сдвинуть цифры влево,
            // и добавляем извлеченную последнюю цифру (pop).
            rev = rev * 10 + pop;
        }
        
        // Когда цикл завершается, rev содержит перевернутое число.
        // Возвращаем результат.
        return rev;
    }
}
```

### 4. Пошаговый разбор для каждого примера

#### Пример 1: `x = 123`

*   **Начало:** `rev = 0`, `x = 123`
*   **Итерация 1:**
    1.  `pop = 123 % 10 = 3`
    2.  `x = 123 / 10 = 12`
    3.  Проверка переполнения: `rev` (0) не вызывает переполнения.
    4.  `rev = 0 * 10 + 3 = 3`
*   **Итерация 2:**
    1.  `pop = 12 % 10 = 2`
    2.  `x = 12 / 10 = 1`
    3.  Проверка переполнения: `rev` (3) не вызывает переполнения.
    4.  `rev = 3 * 10 + 2 = 32`
*   **Итерация 3:**
    1.  `pop = 1 % 10 = 1`
    2.  `x = 1 / 10 = 0`
    3.  Проверка переполнения: `rev` (32) не вызывает переполнения.
    4.  `rev = 32 * 10 + 1 = 321`
*   **Цикл заканчивается**, так как `x == 0`.
*   **Результат:** `321`

#### Пример 2: `x = -123`

*   **Начало:** `rev = 0`, `x = -123`
*   **Итерация 1:**
    1.  `pop = -123 % 10 = -3` (в Java остаток сохраняет знак делимого)
    2.  `x = -123 / 10 = -12`
    3.  Проверка переполнения: `rev` (0) не вызывает переполнения.
    4.  `rev = 0 * 10 + (-3) = -3`
*   **Итерация 2:**
    1.  `pop = -12 % 10 = -2`
    2.  `x = -12 / 10 = -1`
    3.  Проверка переполнения: `rev` (-3) не вызывает переполнения.
    4.  `rev = -3 * 10 + (-2) = -32`
*   **Итерация 3:**
    1.  `pop = -1 % 10 = -1`
    2.  `x = -1 / 10 = 0`
    3.  Проверка переполнения: `rev` (-32) не вызывает переполнения.
    4.  `rev = -32 * 10 + (-1) = -321`
*   **Цикл заканчивается**, так как `x == 0`.
*   **Результат:** `-321`

#### Пример 3: `x = 120`

*   **Начало:** `rev = 0`, `x = 120`
*   **Итерация 1:**
    1.  `pop = 120 % 10 = 0`
    2.  `x = 120 / 10 = 12`
    3.  Проверка переполнения: `rev` (0) не вызывает переполнения.
    4.  `rev = 0 * 10 + 0 = 0`
*   **Итерация 2:**
    1.  `pop = 12 % 10 = 2`
    2.  `x = 12 / 10 = 1`
    3.  Проверка переполнения: `rev` (0) не вызывает переполнения.
    4.  `rev = 0 * 10 + 2 = 2`
*   **Итерация 3:**
    1.  `pop = 1 % 10 = 1`
    2.  `x = 1 / 10 = 0`
    3.  Проверка переполнения: `rev` (2) не вызывает переполнения.
    4.  `rev = 2 * 10 + 1 = 21`
*   **Цикл заканчивается**, так как `x == 0`.
*   **Результат:** `21`
    *(Обратите внимание, что ведущий ноль в результате 021 теряется, так как это целое число, и возвращается 21, 
что соответствует примеру)*.

### 5. Анализ сложности

*   **Временная сложность:** `O(log10(x))` или `O(N)`, где `N` — количество цифр в числе. 
Цикл выполняется столько раз, сколько цифр в числе `x`. Для 32-битного целого числа максимальное количество цифр — 10. 
Поэтому время выполнения фактически константно, но асимптотически зависит от количества цифр.
*   **Пространственная сложность:** `O(1)`. Мы используем только несколько переменных (`rev`, `pop`, `x`), 
* независимо от размера входного числа. Память не растет.

Это решение является оптимальным как по времени, так и по пространству, и корректно обрабатывает все граничные случаи, 
включая переполнение.
